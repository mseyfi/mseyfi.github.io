    Why this matters

    In the last sessions you read how vision-language models are built: a vision encoder, a connector, and a language model, trained in stages. In this lab you build one. You take a frozen SigLIP image encoder, a small frozen language model (SmolLM2-135M-Instruct), and a two-layer MLP between them. You train the MLP alone on image–caption pairs, then add LoRA adapters and teach the model to answer questions about images. At the end you open the model and look at where its text tokens attend in the image.

    This is the LLaVA recipe at toy scale. LLaVA connected a frozen CLIP encoder to a language model with a trainable projection, trained only the projection on 595K image–caption pairs, and then trained the projection and the language model on 158K instruction examples [Certain]. LLaVA-1.5 replaced the linear projection with a two-layer MLP and used 558K and 665K examples for the two stages [Certain] (session 181). The same parts at almost the same size are inside a real model: SmolVLM-256M uses a SigLIP B/16 encoder of about 93M parameters and SmolLM2-135M as its language model [Certain]. So what you build here is not a cartoon; it is a small cousin of a released model.

    Interview tip“How would you add vision to an existing LLM?” is a very common question. A strong answer names the three parts, says which ones are frozen in which stage and why, explains how image features enter the LLM (as input embeddings at the place of a placeholder token), and says how you would check that the model really uses the image, for example with a shuffled-image control.

    The lab answers four practical questions that papers often skip:

    1. What exactly goes into the language model? You will build the input sequence by hand: text embeddings, image embeddings, and a label mask (Figure 1).
    2. Can a tiny MLP, trained alone, make a frozen LLM “see”? You will train it and measure the caption loss with the right image, a wrong image and no image (Figure 2).
    3. What does instruction tuning with LoRA add on top? You will measure question-answering accuracy before and after, with and without Stage 1, and with shuffled images (Figure 3).
    4. Where do the text tokens look? You will read the attention weights from text positions to image positions, layer by layer (Figures 4 and 5).

On a CUDA GPU the losses and accuracies will be close but not identical, because the floating-point kernels differ.

    Step 1: what goes into the language model

    A language model only takes one kind of input: a sequence of vectors, one per position, each of width \(d_{\text{LLM}} = 576\) for SmolLM2. Normally these vectors come from the embedding table: token id in, row of the table out. A VLM of the LLaVA type adds a second source. The image is turned into a few vectors of the same width, and they are placed in the sequence where text embeddings would go. The language model does not know that they are not words. This design is called the unified sequence or adapter approach (session 179).

    The image path has three steps. First, SigLIP cuts the 224 × 224 image into 16 × 16 patches and returns one vector per patch:

    \[ Z = f_{\text{SigLIP}}(x) \in \R^{N \times d_v}, \qquad N = \left(\frac{224}{16}\right)^2 = 14^2 = 196, \quad d_v = 768 \tag{185.1} \]

    Second, we merge each 2 × 2 block of neighbouring patches into one vector by putting the four vectors side by side. This is the “pixel shuffle” (also called space-to-depth) that SmolVLM and InternVL use to cut the number of image tokens [Certain] (session 183). It loses no information, it only reshapes:

    \[ \tilde{\mathbf{z}}_{(i,j)} = \big[\, \mathbf{z}_{(2i,2j)};\ \mathbf{z}_{(2i,2j+1)};\ \mathbf{z}_{(2i+1,2j)};\ \mathbf{z}_{(2i+1,2j+1)} \,\big] \in \R^{4 d_v}, \qquad 0 \le i, j \lt 7 \tag{185.2} \]

    Third, a two-layer MLP maps each merged vector to the LLM’s width:

    \[ \mathbf{h}_{(i,j)} = W_2\, \operatorname{GELU}\!\big(W_1 \tilde{\mathbf{z}}_{(i,j)} + \mathbf{b}_1\big) + \mathbf{b}_2, \qquad W_1 \in \R^{576 \times 3072},\ W_2 \in \R^{576 \times 576} \tag{185.3} \]
    Read the symbols
    \(x\)
    the input image, resized to 224 × 224
    \(Z\)
    SigLIP’s output: one row \(\mathbf{z}_{(r,c)}\) of 768 numbers per patch at row \(r\) and column \(c\) of the 14 × 14 grid
    \(\tilde{\mathbf{z}}_{(i,j)}\)
    the four patches of block \((i,j)\) concatenated: 3,072 numbers; there are \(7 \times 7 = 49\) blocks
    \(W_1, \mathbf{b}_1, W_2, \mathbf{b}_2\)
    the projector’s weights and biases: the only weights trained in Stage 1
    \(\mathbf{h}_{(i,j)}\)
    one image token: a vector of 576 numbers that the LLM reads like a word embedding

    Why merge? Every image token costs the LLM as much compute as a word, in every layer. With 196 tokens per image, the image would be about 90% of a short training sequence. LLaVA-1.5 passes all 576 patch tokens of its 336 px CLIP encoder to the LLM [Certain]; small models such as SmolVLM merge aggressively because the LLM is the expensive part [Certain]. Here the merge makes the lab four times cheaper and still keeps a 7 × 7 spatial map, which is enough to see where the model looks.

    Then we build the sequence. SmolLM2-Instruct was trained with the ChatML template: every turn starts with <|im_start|> and the role, and ends with <|im_end|>. We put the 49 image tokens right after the user header, before the question:

    \[ S = \big[\ E(\text{header}),\ \ \mathbf{h}_{1}, \dots, \mathbf{h}_{49},\ \ E(\text{question} + \text{turn switch}),\ \ E(\text{answer} + \text{end})\ \big] \tag{185.4} \]
    Read the symbols
    \(E(\cdot)\)
    the frozen token embedding table of SmolLM2, applied to the token ids of a piece of text
    header
    <|im_start|>user and a newline: 3 tokens
    \(\mathbf{h}_1, \dots, \mathbf{h}_{49}\)
    the image tokens from (185.3), in row order of the 7 × 7 grid
    turn switch
    <|im_end|>, a newline, <|im_start|>assistant and a newline: 6 tokens
    end
    <|im_end|>, which SmolLM2 uses as its end-of-sequence token (id 2)

    The model is trained with the normal next-token loss, but only on the answer. Every other position gets the label −100, which PyTorch’s cross-entropy skips. We do not want the model to spend capacity predicting the chat template or the question, and it cannot predict image tokens at all, because they are not in its vocabulary.     Worked example: count the parameters and the positions

    Projector. \(W_1\): \(3072 \times 576 = 1{,}769{,}472\) weights plus 576 biases; \(W_2\): \(576 \times 576 = 331{,}776\) plus 576. Total \(1{,}769{,}472 + 576 + 331{,}776 + 576 = 2{,}102{,}400\). Without the merge (input 768) it would be \(442{,}368 + 576 + 331{,}776 + 576 = 775{,}296\).

    Share trained in Stage 1. All parameters: \(92{,}884{,}224 + 2{,}102{,}400 + 134{,}515{,}008 = 229{,}501{,}632\). We train \(2{,}102{,}400\), which is 0.92% of them.

    Positions. For the question “What is in this image? Answer with one word.” the tokenizer gives 3 header tokens, then 49 image tokens, then 17 tokens for the question and the assistant header: 69 positions before the answer. The answer “cat” is 1 token plus <|im_end|>. Image tokens are \(49 / 69 = 71\%\) of the context. With all 196 patches they would be \(196 / 216 = 90.7\%\).

    Step 2: run the vision encoder once

    The vision encoder is frozen in both stages, so its output for an image never changes. Run it once over all images and store the result, exactly as in the linear-probe lab (session 171). Training then never touches SigLIP; each step reads 196 × 768 numbers per image from disk.

    Algorithm 2: extract and cache the image features
    1. input: images, the SigLIP vision tower in eval() mode, its image processor
    2. for each batch of 64 images do
    3.   resize to 224 × 224 and normalize with the processor // SigLIP maps pixels to [−1, 1]
    4.   \(Z \leftarrow\) last_hidden_state with gradients off // 196 × 768, after SigLIP’s final LayerNorm
    5.   store \(Z\) in FP16 together with the captions or labels, in the same order
    6. end for

    We keep the patch tokens, not the pooled vector. The pooled output of SigLIP’s attention-pooling head is one vector per image, which is good for retrieval but throws away where things are. A VLM needs the spatial map, so LLaVA-style models read the patch tokens of a late layer [Certain]. (LLaVA uses the second-to-last layer of CLIP [Likely]; we use the last layer of SigLIP for simplicity. Exercise 5 asks you to compare.)

    Worked example: how big is the cache?

    Each image gives \(196 \times 768 = 150{,}528\) numbers, 301 KB in FP16. Flickr8k’s 8,000 images take \(8{,}000 \times 150{,}528 \times 2 = 2.41\) GB; the 6,000 training images alone 1.81 GB, which matches the file we saved. The 6,000 CIFAR-10 images take another 1.81 GB. Load the big files with torch.load(..., mmap=True) so the operating system reads only the rows each batch needs.

    Step 3: Stage 1, align the projector on captions

    At the start the projector is random, so the image tokens are noise to the LLM. Stage 1 has one job: make the image tokens mean something to the frozen LLM. The task is captioning, because a caption is the simplest text that depends on the image. The question is always “Describe the image.” and the answer is one of the five human captions. The LLM and SigLIP stay frozen; gradients flow back through the frozen LLM into the projector, but only the projector’s weights change. LLaVA calls this stage “pre-training for feature alignment” [Certain].

    The loss is the average next-token cross-entropy over the answer tokens of a batch:

    \[ \mathcal{L}(\theta) = -\frac{1}{\sum_b |A_b|} \sum_{b} \sum_{t \in A_b} \log p_{\text{LLM}}\big(s_{b,t+1} \mid S_{b,\le t}\big), \qquad S_b = \big[P;\ \text{Proj}_\theta(Z_b);\ Q;\ A_b\big] \tag{185.5} \]
    Read the symbols
    \(\theta\)
    the projector’s weights, the only trainable parameters in Stage 1
    \(b\)
    an example in the batch (32 per batch)
    \(A_b\)
    the set of positions \(t\) whose next token \(s_{b,t+1}\) belongs to the answer (caption tokens and the final <|im_end|>); these are the positions whose label is not −100
    \(S_{b,\le t}\)
    the sequence up to position \(t\): header, image tokens, question, and the answer so far
    \(p_{\text{LLM}}\)
    the frozen LLM’s next-token probability

    One practical detail saves a lot of memory. The full logits tensor for a batch is \(B \times L \times V\) numbers: with 32 examples, about 75 positions and a vocabulary of 49,152, that is 118 million numbers, 472 MB in FP32, plus the same again for its gradient. But only the answer positions need logits. So we run the LLM body, pick the hidden states at the answer positions, and apply the output layer only there. The loss is the same; the memory for logits falls by a factor of about five.

    Algorithm 3: Stage 1 training loop
    1. input: cached features of 6,000 training images, 5 captions each; projector \(\theta\) (random); frozen LLM
    2. freeze every LLM parameter (requires_grad = False); optimizer AdamW on \(\theta\) only, learning rate \(10^{-3}\), weight decay 0
    3. for epoch in 1, 2 do // each epoch: every image once, with one of its 5 captions chosen at random
    4.   for each batch of 32 do
    5.     build the sequences and labels (Algorithm 1) with question “Describe the image.”
    6.     \(\mathcal{L} \leftarrow\) formula (185.5); backpropagate; AdamW step // warmup 20 steps, then cosine decay
    7.     every 25 steps: validation loss on 256 held-out images
    8.   end for
    9. end for // 2 × 6,000 / 32 = 375 steps

    This is close to LLaVA-1.5’s Stage 1 recipe (AdamW, learning rate \(10^{-3}\), cosine decay with warmup, no weight decay, one epoch [Certain]), with a smaller batch (32 against 256) because our dataset is 93 times smaller (6,000 against 558K images). The run took 931 seconds on our shared laptop GPU.

    Does the model use the image? The shuffled-image control

    A falling loss is not yet proof. The projector could learn to say “this is a Flickr caption” (short sentences, “A dog …”, “A man in a …”) without passing any content of the photo. To separate the two, evaluate the same captions three ways: with the right image, with a wrong image (every image swapped with its neighbour in the list), and with no image at all (the image tokens removed). The difference between wrong and right is what the image content is worth:

    \[ \Delta_{\text{img}} = \mathcal{L}_{\text{wrong image}} - \mathcal{L}_{\text{right image}}, \qquad \frac{\operatorname{PPL}_{\text{wrong}}}{\operatorname{PPL}_{\text{right}}} = e^{\Delta_{\text{img}}} \tag{185.6} \]
    Read the symbols
    \(\mathcal{L}\)
    the mean caption loss (185.5) over the 1,000 validation images, in nats per token
    \(\operatorname{PPL} = e^{\mathcal{L}}\)
    perplexity: roughly, among how many equally likely tokens the model is choosing at each step

    • No image gives exactly the same loss before and after (4.353). This is a good sanity check: without image tokens, nothing in the computation changed, because the LLM is frozen.
    • Wrong image falls from 4.274 to 3.402, by 0.876 nats. This part of the gain needs an image but not the image: the projector learned to signal “write a short photo caption”. That is style, not seeing.

    Step 4: Stage 2, instruction tuning with LoRA

    After Stage 1 the model can see, but it cannot follow instructions about what it sees. Ask it “What is in this image? Answer with one word.” and it answers like a captioner. Our Stage-1 model’s first five answers on CIFAR-10 test images were “The image is a dog”, “The image is a beach”, “The dog is a toy”, “The image is a car” and “The bird is in the”. Some are even right about the content, but none is one word, so a strict scorer gives 0.0%. To the yes/no question it answered “Yes” every time.

    Stage 2 teaches the format and the skill of answering. LLaVA unfreezes the whole LLM here [Certain]. We use LoRA instead (session 57): the LLM’s weights stay frozen, and a small trainable low-rank update is added to some of its matrices. The projector keeps training too.

    \[ W' \mathbf{x} = W \mathbf{x} + \frac{\alpha}{r}\, B A\, \mathbf{x}, \qquad A \in \R^{r \times d_{\text{in}}},\ \ B \in \R^{d_{\text{out}} \times r},\ \ B_{\text{init}} = 0 \tag{185.7} \]
    Read the symbols
    \(W\)
    a frozen weight matrix of the LLM; we adapt the query projection q_proj (576 → 576) and the value projection v_proj (576 → 192, because SmolLM2 has only 3 key-value heads of width 64) in all 30 layers
    \(A, B\)
    the trainable LoRA matrices; \(A\) starts random and \(B\) starts at zero, so at step 0 the model is exactly the Stage 1 model
    \(r\)
    the rank, 8 here
    \(\alpha\)
    a scale, 16 here, so the update is multiplied by \(\alpha / r = 2\)

    The number of LoRA parameters is

    \[ n_{\text{LoRA}} = L \cdot r \cdot \big[(d + d) + (d + d_{kv})\big] = 30 \cdot 8 \cdot \big[(576 + 576) + (576 + 192)\big] = 460{,}800 \tag{185.8} \]

    With the projector, Stage 2 trains \(2{,}102{,}400 + 460{,}800 = 2{,}563{,}200\) parameters, about 1.1% of the model.

    The VQA set

    For every CIFAR-10 image we write three questions whose answers come from the label:

    • “What is in this image? Answer with one word.” The class name (airplane, automobile, bird, cat, deer, dog, frog, horse, ship, truck). Chance: 10%.
    • “Is this an animal or a vehicle? Answer with one word.” Six classes are animals and four are vehicles; on our balanced test set, always saying “animal” scores 60%.
    • “Is there a … in this image? Answer yes or no.” With probability one half the named class is the true one, otherwise a random other class. On our test set “yes” is the right answer 50.0% of the time.

    That gives 15,000 training questions (5,000 images) and 3,000 test questions (1,000 different images). We train one epoch: 468 steps of 32, AdamW, learning rate \(2 \times 10^{-4}\) with 20 warmup steps and cosine decay, for the LoRA matrices and the projector together. The answer is scored by its first word, lower-cased, with punctuation removed. CIFAR-10 images are 32 × 32 pixels, so SigLIP sees them blown up to 224 × 224: a hard, blurry input, but every answer is checkable.

    Four things to read from it.

    • Stage 2 works, and it uses the image. 94.3% on a ten-way question about 32-pixel images, from a 135M LLM that never saw CIFAR-10. With swapped images every question type falls to chance: 8.9% (chance 10%), 51.4% and 49.4%. For “animal or vehicle?” with random pairs, the expected score is \(0.6^2 + 0.4^2 = 52\%\), which is what we see. So the answers come from the image, not from the question.
    • Yes/no is the hardest. 86.6% against 94.3% for naming the class, although it seems easier. The model must compare the image with a class named in the question, and the answer token does not contain the class: a check, not a lookup. “Is there a … in the image?” is also the exact format of POPE, the standard test for object hallucination in VLMs [Certain] (session 193).
    • Stage 1 did not help here, and this surprised us. We expected the run without Stage 1 to be clearly worse. It was not: from a random projector, Stage 2 reached 94.4%, 99.5% and 95.0%, equal on the first two questions and 8.4 points better on yes/no. The Stage 1 projector only gave a faster start: smoothed training loss 1.05 against 1.97 after 25 steps, the same by step 100 (Figure 3, “Loss curves”). This agrees with the Prismatic study, which found that the projector-only alignment stage of LLaVA-1.5 is unnecessary and that single-stage training even improves the average score, while saving 20 to 25% of the training cost [Certain]. Our task is also easy for single-stage training: a closed set of short answers with 15,000 examples. Why the Stage 1 projector does worse on yes/no we do not know; one guess is that its caption-shaped features plus the Stage 1 model’s “Yes” habit make the yes/no check harder to learn in one epoch [Speculation]. This is one seed per setting; the 8.4-point gap is much larger than the test noise (about 1 point), but a different seed could change it [Likely].
    • Stage 2 makes the model forget how to caption. We measured the Flickr8k caption loss again with the Stage 2 weights: 3.572, against 2.607 after Stage 1, which is worse than Stage 1 with a wrong image (3.402). 468 steps of one-word answers taught the model that answers are one word. This is why real Stage 2 data are a mixture: LLaVA-1.5’s 665K examples combine conversations, detailed descriptions, short-answer VQA with a format prompt, and other tasks [Certain] (session 186).
    Interview tip“Is the alignment stage necessary?” has no single answer, and saying so with evidence is the strong answer. The argument for it: a random projector sends noise into the LLM at the start, and caption data are cheap. The evidence against it: Prismatic, and our lab, where single-stage training matched or beat two stages. It matters more when the LLM is fully unfrozen (noise can damage it) and when the Stage 2 data are small or diverse.

    Step 5: where do the text tokens look?

    The image enters the LLM only through attention: a text position can use an image token only by attending to it. So the attention weights show, in a rough way, how much each text position reads from the image. In layer \(\ell\), head \(h\), the attention row of position \(t\) is a probability distribution over the positions \(j \le t\) (session 17). We average it over the 9 heads and add up the part that falls on the 49 image positions:

    \[ m^{\ell}_{t} = \sum_{j \in \mathcal{I}} \bar{a}^{\ell}_{t j}, \qquad \bar{a}^{\ell}_{t j} = \frac{1}{H} \sum_{h=1}^{H} \softmax_j\!\Big(\frac{\mathbf{q}^{\ell,h}_t \cdot \mathbf{k}^{\ell,h}_j}{\sqrt{d_h}}\Big) \tag{185.9} \]
    Read the symbols
    \(m^{\ell}_t\)
    the image attention mass: the share of position \(t\)’s attention in layer \(\ell\) that goes to image tokens, between 0 and 1
    \(\mathcal{I}\)
    the 49 positions of the image tokens (positions 3 to 51)
    \(\mathbf{q}^{\ell,h}_t, \mathbf{k}^{\ell,h}_j\)
    the query of position \(t\) and the key of position \(j\) in head \(h\); \(d_h = 64\)
    \(H\)
    the number of query heads, 9

    Which position \(t\)? The one that predicts the word we care about: to study the word “dogs”, take the row of the token just before it. The baseline is the share of image positions in the context: if attention were spread evenly, \(m\) would equal that share (49 of 69 positions, 71%, for the class question). To get attention weights from Hugging Face, load the model with attn_implementation="eager"; the fused SDPA kernel does not return them.

    Algorithm 5: attention from text to image
    1. load the LLM with eager attention; build the sequence (Algorithm 1) with the model’s own caption or the question
    2. one forward pass with output_attentions=True // 30 tensors of shape (1, 9, L, L)
    3. average over heads; for each word, take the row \(t\) that predicts it
    4. \(m^\ell_t \leftarrow\) the sum of that row over the image positions (185.9); the 49 values themselves, reshaped to 7 × 7, are the map
    5. compare with the baseline 49 / (number of context positions), and with the attention on the first token

    Maps while the model writes a caption

    Figure 4 uses the Stage 1 model on four Flickr8k test images. For each word of its own caption you see the attention to the 7 × 7 image tokens. We looked at the raw maps first, and they are disappointing in an instructive way: for almost every word and layer band, the strongest image token is the first one, the top-left corner, in row 1, column 1, whatever the word. The maps for different words of the same caption are very similar (average cosine similarity between 0.90 and 0.98 over all layers, depending on the image). The first image position behaves like a small extra attention sink, the same effect as the large attention to the first token of a sequence that StreamingLLM described [Certain] (session 116).

    So the figure has a second mode, “Minus caption average”: from each word’s map we subtract the average map of all the words of that caption and keep the positive part. What remains is what is special about this word. Now “dogs” lights up the two dogs, and “woman” the people under the umbrella, while “snow” and “the” go to background tokens. This is a qualitative look at four images, not a measurement.

    One number is clearer. In all four captions, the word that receives the most image attention (all layers) is the noun that names the main subject: “dogs” (20.7%), “woman” (16.2%), “dog” (18.7%) and “man” (19.2%). Function words such as “of” and “and” get about 10% to 12%. The model reads the image most when it has to name what is in it.

    How much attention goes to the image, layer by layer

    Now take the Stage 2 model and the position that predicts the one-word answer, averaged over 100 test images. Figure 5 shows the image mass (185.9) in each layer, next to the mass on the first token and on the text.

    Three lessons from Figure 5.

    • Image tokens get far less attention than their number suggests. They are 71% of the positions and get 17% of the attention on average. This is the observation behind FastV, which found that image tokens receive little attention after the first layers of LLaVA-style models and drops many of them at inference [Certain]. In our model layers 2 and 3 nearly ignore the image; we have not tested how many tokens could be dropped (Exercise 6).
    • The reading is concentrated in a few layers. For the class question, three layers (22 to 24) carry half or more of their attention to the image. For the coarse animal-or-vehicle question those layers stay low. One possible reason is that the coarse decision needs less detail, so it is read earlier or from fewer tokens [Speculation]; attention alone cannot prove it. A causal test is to block attention to image tokens in only those layers and measure the accuracy drop.
    • Attention is not explanation. The first-token sink, the corner-token sink of Figure 4 and the head averaging all mix with content. Use attention mass as a cheap diagnostic (“does the answer read the image at all, and where?”), and use interventions, such as the shuffled-image control or blocking attention, to make claims.

    import torch, torch.nn as nn, math, random, numpy as np
from transformers import AutoModelForCausalLM, AutoTokenizer
DEV = "mps"
LLM = "HuggingFaceTB/SmolLM2-135M-Instruct"
GRID, MERGE, D_VIS = 14, 2, 768          # SigLIP: 14 x 14 patches of 768; merge 2 x 2 neighbours
N_IMG = (GRID // MERGE) ** 2              # 49 image tokens go into the LLM

def seed_all(s=0):
    random.seed(s); np.random.seed(s); torch.manual_seed(s)

class Projector(nn.Module):
    """Pixel-shuffle 2 x 2 neighbouring patches into one vector (4 x 768 = 3072), then a
    LLaVA-1.5 style MLP: Linear -> GELU -> Linear. 196 patches in, 49 tokens of width 576 out."""
    def __init__(self, d_vis=768, d_llm=576, r=MERGE):
        super().__init__()
        self.r = r
        self.net = nn.Sequential(nn.Linear(d_vis * r * r, d_llm), nn.GELU(), nn.Linear(d_llm, d_llm))
    def forward(self, v):                                   # v: (B, 196, 768)
        B, N, d = v.shape; g = int(N ** 0.5); r = self.r
        v = v.view(B, g // r, r, g // r, r, d).permute(0, 1, 3, 2, 4, 5)   # (B, 7, 7, 2, 2, 768)
        return self.net(v.reshape(B, (g // r) ** 2, r * r * d))           # (B, 49, 576)

class LoRALinear(nn.Module):
    def __init__(self, base, r=8, alpha=16):
        super().__init__()
        self.base = base; self.r = r; self.scale = alpha / r
        self.A = nn.Parameter(torch.randn(r, base.in_features) / math.sqrt(base.in_features))
        self.B = nn.Parameter(torch.zeros(base.out_features, r))
    def forward(self, x):
        return self.base(x) + (x @ self.A.t() @ self.B.t()) * self.scale

def load_llm(attn="sdpa"):
    tok = AutoTokenizer.from_pretrained(LLM)
    llm = AutoModelForCausalLM.from_pretrained(LLM, torch_dtype=torch.float32, attn_implementation=attn).to(DEV)
    for p in llm.parameters(): p.requires_grad_(False)
    return tok, llm

def add_lora(llm, r=8, alpha=16, targets=("q_proj", "v_proj")):
    for layer in llm.model.layers:
        for t in targets:
            setattr(layer.self_attn, t, LoRALinear(getattr(layer.self_attn, t), r, alpha).to(DEV))
    return [p for n, p in llm.named_parameters() if n.endswith(".A") or n.endswith(".B")]

class Builder:
    """Turns (image features, question, answer) into one sequence of embeddings + labels."""
    def __init__(self, tok):
        self.tok = tok
        self.pre = tok("<|im_start|>user\n").input_ids            # 3 tokens, image goes right after
    def ids(self, q, a=None):
        suf = self.tok(q + "<|im_end|>\n<|im_start|>assistant\n").input_ids
        ans = self.tok(a + "<|im_end|>").input_ids if a is not None else []
        return suf, ans
    def batch(self, llm, proj, feats, qs, ans, use_image=True, left_pad=False):
        """feats: (B,196,768) fp16 on cpu. Returns inputs_embeds, attention_mask, labels."""
        E = llm.get_input_embeddings()
        B = len(qs); rows = []
        img = proj(feats.to(DEV).float()) if use_image else None
        for i in range(B):
            suf, a = self.ids(qs[i], ans[i] if ans is not None else None)
            pre_e = E(torch.tensor(self.pre, device=DEV))
            txt_e = E(torch.tensor(suf + a, device=DEV))
            parts = [pre_e] + ([img[i]] if use_image else []) + [txt_e]
            emb = torch.cat(parts)
            n_ctx = len(self.pre) + (N_IMG if use_image else 0) + len(suf)
            lab = [-100] * n_ctx + a
            rows.append((emb, lab))
        L = max(r[0].shape[0] for r in rows); d = rows[0][0].shape[1]
        emb = torch.zeros(B, L, d, device=DEV); mask = torch.zeros(B, L, dtype=torch.long, device=DEV)
        labels = torch.full((B, L), -100, dtype=torch.long, device=DEV)
        for i, (e, lab) in enumerate(rows):
            n = e.shape[0]
            s = L - n if left_pad else 0
            emb[i, s:s+n] = e; mask[i, s:s+n] = 1
            labels[i, s:s+n] = torch.tensor(lab, device=DEV)
        return emb, mask, labels

def answer_loss(llm, emb, mask, lab, reduction="mean"):
    """Next-token cross-entropy on answer tokens only. We run the LM head only at the positions
    that predict an answer token, so we never build the full (B, L, 49152) logits tensor."""
    h = llm.model(inputs_embeds=emb, attention_mask=mask).last_hidden_state   # (B, L, 576)
    tgt = lab[:, 1:]; keep = tgt != -100                                        # position t predicts token t+1
    logits = llm.lm_head(h[:, :-1][keep])                                       # (n_answer_tokens, 49152)
    return nn.functional.cross_entropy(logits, tgt[keep], reduction=reduction), int(keep.sum())

@torch.no_grad()
def mean_loss(llm, proj, bld, feats, qs, ans, use_image=True, bs=32):
    tot, cnt = 0.0, 0
    for i in range(0, len(qs), bs):
        emb, mask, lab = bld.batch(llm, proj, feats[i:i+bs], qs[i:i+bs], ans[i:i+bs], use_image)
        l, n = answer_loss(llm, emb, mask, lab, reduction="sum")
        tot += l.item(); cnt += n
    return tot / cnt

@torch.no_grad()
def generate(llm, proj, bld, feats, qs, max_new=30, bs=32, use_image=True):
    outs = []
    for i in range(0, len(qs), bs):
        emb, mask, _ = bld.batch(llm, proj, feats[i:i+bs], qs[i:i+bs], None, use_image, left_pad=True)
        g = llm.generate(inputs_embeds=emb, attention_mask=mask, max_new_tokens=max_new, do_sample=False,
                         eos_token_id=2, pad_token_id=2)
        outs += [bld.tok.decode(x, skip_special_tokens=True).strip() for x in g]
    return outs

def cosine_lr(step, total, base, warm):
    if step < warm: return base * (step + 1) / warm
    return base * 0.5 * (1 + math.cos(math.pi * (step - warm) / max(1, total - warm)))

            fs.append(row[:, 0].tolist())                                # first token (attention sink)
            ft.append((row[:, 1:P0].sum(-1) + row[:, P0+N_IMG:].sum(-1)).tolist())
            L0 = emb.shape[1]
        res[qt] = {"img": np.array(fr).mean(0).round(4).tolist(), "first": np.array(fs).mean(0).round(4).tolist(),
                   "text": np.array(ft).mean(0).round(4).tolist(), "L": L0}
        print(qt, L0, np.array(fr).mean(), flush=True)
R["s2_frac"] = res
json.dump(R, open("s3.json", "w"))
print("done")

    Common mistakes

    • Putting the loss on every position. If the labels are not −100 outside the answer, the model spends its capacity predicting the chat template and the question, and the loss numbers mean something else. Check the label mask on one printed example before training.
    • Off-by-one in the shift. Position \(t\) predicts token \(t+1\). If you compare logits and labels without the shift, the model learns to copy its input and the loss falls fast for the wrong reason. Hugging Face shifts inside the model when you pass labels; if you compute the loss yourself (as we do, to save memory), shift yourself.
    • No shuffled-image control. A falling caption loss does not prove the model looks at the image: it may only learn caption style. Always report the loss or accuracy with each image swapped for another one. The gap is the evidence.
    • Wrong feature layer or normalization. Using SigLIP’s pooled vector instead of the patch tokens, or feeding images normalized for another encoder, fails silently: training runs, but the image carries less.
    • Learning rate from LLM fine-tuning for the projector. A fresh projector needs a large rate (LLaVA-1.5 uses \(10^{-3}\) [Certain]); with \(2 \times 10^{-5}\) it hardly moves in one epoch. In Stage 2, the LoRA rate should be lower (we use \(2 \times 10^{-4}\)).
    • Left padding forgotten at generation. For batched generation the prompts must be padded on the left, so that every row ends at the position that predicts the first answer token. Right padding makes rows continue after pad tokens.
    • Deciding a recipe question from one task and one seed. In our lab Stage 1 did not help on closed-set VQA; on open-ended captioning or with a fully unfrozen LLM it may. Test recipe choices on the evaluation you care about, with at least two seeds.
    • Reading raw attention maps as explanations. Head-averaged attention mixes sink tokens, position effects and real content. Report the attention mass with a baseline (the share of image tokens in the sequence) and look at many examples before you draw a conclusion.

    Interview questions

    Describe the architecture of a LLaVA-style VLM. How does the image get into the language model?basic
    Three parts: a pretrained vision encoder (CLIP or SigLIP ViT), a small connector (a linear layer or a two-layer MLP, sometimes after merging neighbouring patches), and a decoder-only LLM. The encoder’s patch tokens go through the connector and come out with the LLM’s embedding width. They are inserted into the input sequence as embeddings, at the place of an image placeholder in the chat template, next to the ordinary token embeddings, and passed with inputs_embeds. The LLM then treats them like words; text positions read them through normal causal self-attention. In our lab: 196 SigLIP patches, merged to 49 tokens, MLP to width 576.
    Why freeze both the encoder and the LLM in Stage 1, and train only the projector?basic
    At the start the projector is random, so the image tokens are noise. If the LLM were trainable, its weights would be pushed around by gradients that come from noise, which can damage its language ability. Training only the projector is also cheap (2.1M parameters here, under 1% of the model) and the task is simple: map one feature space into another that already exists. Caption pairs are plentiful, so this alignment uses cheap data. LLaVA and LLaVA-1.5 freeze both in Stage 1 for these reasons.
    Why are the labels −100 everywhere except the answer?basic
    −100 is the default ignore_index of PyTorch’s cross-entropy, so those positions add no loss and no gradient. The image positions cannot have a label at all (image tokens are not vocabulary items), and the template and question are given, not generated, so training on them wastes capacity and makes the loss harder to interpret. The loss is then the average over answer tokens only. Remember the shift: position \(t\) predicts the token at \(t+1\).
    Your caption loss went down. How do you show that the model actually uses the image?core
    Evaluate the same text with the right image, a wrong image (shuffle images across examples) and no image. The difference between wrong and right is the image content. In our run the loss fell from 4.28 to 2.61 with the right image, but also from 4.27 to 3.40 with a wrong image: about half of the gain was caption style that any image triggers. The content gain was 0.795 nats per token, a 2.2 times lower perplexity. For question answering, the same control dropped accuracy from 94.3% to 8.9%, which is chance.
    How does LoRA work, how many parameters did it add here, and why does it start from the Stage 1 model exactly?core
    LoRA keeps \(W\) frozen and adds \(\frac{\alpha}{r} B A\) with \(A \in \R^{r \times d_{in}}\), \(B \in \R^{d_{out} \times r}\). With \(r = 8\) on q_proj (576 → 576) and v_proj (576 → 192, because of 3 key-value heads) in 30 layers, that is \(30 \cdot 8 \cdot (1152 + 768) = 460{,}800\) parameters. \(B\) is initialized to zero, so \(BA = 0\) and the model at step 0 is exactly the Stage 1 model; training only moves away from it as needed. The update can be merged into \(W\) after training, so inference costs nothing extra.
    Why merge 2 × 2 patches before the projector? What do you lose?core
    Every image token costs the LLM as much as a word in every layer, in compute and in KV cache. Merging (pixel shuffle) concatenates four neighbouring patch vectors into one, so 196 tokens become 49 with no information thrown away at the input: the projector sees all 3,072 numbers. What you lose is spatial resolution in the LLM’s attention (it can point only to 7 × 7 cells) and possibly fine detail, since the MLP must compress four patches into one 576-number vector. Small models such as SmolVLM merge aggressively; LLaVA-1.5 does not merge and passes 576 tokens.
    After Stage 1 the model captions well but scores 0% on “What is in this image? Answer with one word.” Why?core
    Stage 1 only taught the model to describe images; it never saw an instruction about the answer format. It answered “The image is a dog”, often right in content but not one word, so a strict scorer gives 0. Seeing and following instructions are different skills: Stage 2 (visual instruction tuning) teaches the second. A fair evaluation either fixes the format with a prompt and a scorer that extracts the answer, or tunes the model on the format.
    After Stage 2 the caption loss got worse than with a wrong image. What happened, and how do real recipes avoid it?core
    Catastrophic forgetting through narrow data: 468 steps of one-word answers taught the projector and the LoRA weights that answers are short, so long captions became unlikely (loss 3.572 against 2.607). Real Stage 2 data are a mixture of task types and answer lengths; LLaVA-1.5 mixes conversations, detailed descriptions, short VQA with an explicit format instruction, and more. Other fixes: replay some Stage 1 caption data, use a lower learning rate or fewer steps, keep the projector frozen in Stage 2, or keep separate LoRA adapters per task.
    How would you measure where a VLM looks, and what are the traps?advanced
    Run with eager attention and output_attentions=True, take the row of the position that predicts the word of interest, average over heads, and sum over image positions to get the image attention mass per layer, or reshape the image part into the patch grid for a map. Compare with the baseline share of image positions. Traps: attention sinks (the first token took up to 84% in deep layers; the first image token was a sink inside the image), head averaging hides specialized heads, and attention weight is not influence, because value vectors differ in size. Use interventions (shuffled images, masking attention to image tokens in some layers) to make causal claims.
    Image tokens were 71% of the positions but got 17% of the attention. What would you do with this observation?advanced
    It suggests that many image tokens are not needed in many layers, which is what FastV used: it drops a large part of the image tokens after layer 2 based on their attention scores, with small accuracy loss on LLaVA-style models. Before relying on it, measure: drop tokens in some layers and check accuracy, per task, because the class question in our model read the image heavily in layers 22 to 24 while the coarse question did not. For training-time savings, merge tokens before the LLM (pixel shuffle, pooling, a resampler) instead.
    How would you turn this mini-VLM into a video question-answering model?advanced
    Sample frames (for example 8 to 32 per clip), run the frozen encoder per frame and cache the features, merge or pool tokens per frame so that the total fits the context budget (32 frames × 49 tokens = 1,568 tokens here), add time information (frame order, timestamps in text, or temporal position ids), and train Stage 1 on video–caption pairs and Stage 2 on video QA, including questions about order and key moments. Keep the shuffled control: shuffle frames in time to test if the model uses order at all.
    In this lab, Stage 2 from a random projector matched or beat the two-stage model. Does that mean Stage 1 is useless?advanced
    No, it means it was not needed for this task. The task was a closed set of short answers with 15,000 clean examples, and LoRA plus a trainable projector learned it from scratch in one epoch (94.4%, 99.5%, 95.0% against 94.3%, 99.0%, 86.6% with Stage 1). Stage 1 gave a faster start but no better end. Prismatic found the same at real scale: single-stage training was better on average and 20 to 25% cheaper. Stage 1 can still matter when the LLM is fully unfrozen, when instruction data are scarce, or for open-ended generation such as captioning, which our VQA test does not measure. The right answer is to run both on your own evaluation, with more than one seed.

    Key takeaways

    • A LLaVA-style VLM is three parts: a frozen vision encoder, a small projector, and an LLM. Image tokens enter the LLM as input embeddings (185.4); the loss is only on the answer (185.5).
    • Stage 1 trains only the projector (2.1M parameters, 0.92% of our model) on captions. It cut the caption loss from 4.28 to 2.61 nats per token.
    • Always run the wrong-image control: about half of the Stage 1 gain was style; the content gain was 0.795 nats (185.6), a 2.2 times lower perplexity.
    • Stage 2 with LoRA (460,800 parameters, 185.7–185.8) taught instruction following: 94.3%, 99.0% and 86.6% on three question types, falling to chance with wrong images. Skipping Stage 1 gave the same or better accuracy here (as Prismatic found at scale); it only slowed the start.
    • Narrow Stage 2 data cause forgetting: the caption loss rose to 3.572. Real recipes mix many task types.
    • Image tokens were 71% of the positions but got 17% of the attention, concentrated in a few layers; sinks dominate raw maps. Attention is a diagnostic, not an explanation.
