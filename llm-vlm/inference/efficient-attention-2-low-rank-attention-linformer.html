    Efficient attention 2: low-rank attention (Linformer, Luna, Set Transformer)

    Full attention builds an n × n table for every head, so its cost grows with the square of the sequence length. This session shows that this table is often close to low rank, and how Linformer, the Set Transformer and Luna use that to make attention linear in n: project the keys and values to a fixed length, or let a few learned queries pack the sequence and then unpack it. You will also see why these methods are hard to use with causal masking and variable lengths, and where the pack idea lives on in vision-language models.

    Time: 2.5 to 3.5 hours (reading 1.5 to 2 hours, exercises 1 to 1.5 hours)Level: Intermediate to interview levelBefore this: Sessions 17 to 20 (attention, masks, multi-head and cross-attention), 80 (the KV cache) and 93 (where the cost is)

    What you will learn

    • Why full attention costs 4n²d FLOPs and an n × n matrix per head, and what FlashAttention does and does not fix
    • What rank, the SVD and the Eckart–Young theorem tell us about approximating an attention matrix, and which heads are low rank and which are not
    • Linformer: the learned projections E and F, the cost 8nkd, the ratio n/(2k), parameter sharing, and the measured results
    • Set Transformer (ISAB, PMA) and Luna: pack a sequence into l learned summaries, then unpack, with cost linear in n and no dependence on the length
    • Why causal masking and variable lengths break fixed projections, what a causal fix costs, and why decoder LLMs rarely use low-rank attention
    • How the same pack idea appears in VLM connectors (Q-Former, Perceiver Resampler) and in video models

    Why this matters

    Full attention compares every token with every other token. For a sequence of \(n\) tokens, each head builds an \(n \times n\) table of scores. At \(n = 4096\), one head in one layer has 16.8 million scores; in FP16 that is 32 MiB, and with 32 heads it is 1 GiB per layer. Double the length and all of this grows four times.

    In session 93 you saw that this square term takes over at long context, and in session 97 you made the KV cache smaller by sharing keys and values across heads. That did not touch the \(n^2\) term. This session attacks it directly with one idea: the attention matrix often carries much less information than its size suggests. If an \(n \times n\) matrix is close to a matrix of rank \(k\) (it can be written with only \(k\) independent directions), we never need to build the full matrix. We can work with an \(n \times k\) matrix instead, and the cost becomes linear in \(n\).

    The efficient-inference survey of Zhou et al. puts this family under “efficient attention” in its model-level section (5.1.2), next to sparse attention and kernel-based attention. [Certain] We study three members:

    • Linformer (Wang et al., 2020): project the keys and values from length \(n\) down to a fixed length \(k\) with a learned matrix.
    • Set Transformer (Lee et al., 2019) and Luna (Ma et al., 2021): a small set of learned query vectors first reads the whole sequence (“pack”), and then every token reads that small set (“unpack”).
    • A short look at Funnel-Transformer (Dai et al., 2020), which shrinks the sequence itself between blocks.

    Low-rank attention is rarely used inside today’s large decoder-only LLMs, and this session explains why: causal masking and variable lengths are hard for it. But the pack-then-read idea is everywhere in vision-language models. BLIP-2’s Q-Former uses 32 learned queries, and Flamingo’s Perceiver Resampler turns any number of image or video features into 64 visual tokens. [Certain] So the same math you learn here explains how a VLM squeezes a video into a few dozen tokens.

    Interview tipTypical questions: “How does Linformer reach linear complexity?”, “Is the attention matrix really low rank?”, “Why can’t you just use Linformer in GPT?”, “What do Perceiver, Q-Former and Set Transformer have in common?”. Each has a short answer with one formula below.

    The cost we want to remove

    Recall scaled dot-product attention for one head (session 17). The queries \(Q\), keys \(K\) and values \(V\) are \(n \times d\) matrices, one row per token, where \(d\) is the head size:

    \[ P = \softmax\!\left(\frac{Q K^\top}{\sqrt{d}}\right) \in \R^{n \times n}, \qquad O = P V \in \R^{n \times d}, \qquad \text{FLOPs} \approx 4 n^2 d \tag{98.1} \]
    Read the symbols
    \(P\)
    the attention matrix (Linformer calls it the “context mapping matrix”). Row \(i\) holds the weights token \(i\) puts on all \(n\) tokens; each row sums to 1
    \(\softmax\)
    applied to each row separately
    \(O\)
    the output: each row is a weighted average of value rows
    \(4n^2 d\)
    \(2n^2 d\) FLOPs for \(QK^\top\) and \(2n^2 d\) for \(PV\) (a multiply plus an add counts as 2)

    Both the compute and the size of \(P\) grow with \(n^2\). FlashAttention (session 124) removes the memory problem, because it never writes \(P\) to main memory, but it still does all \(4n^2 d\) FLOPs. The methods in this session try to remove the FLOPs too, by never forming an \(n \times n\) matrix at all. The price is that the result is an approximation of full attention, not the exact value.

    Is the attention matrix low rank?

    What rank means here

    The rank of a matrix is the number of independent directions in it. A rank-1 matrix has every row equal to a multiple of one row vector. Any matrix can be split by the singular value decomposition (SVD) into a sum of rank-1 pieces, sorted from most to least important:

    \[ P = \sum_{i=1}^{n} \sigma_i\, \mathbf{u}_i \mathbf{v}_i^\top, \qquad \sigma_1 \ge \sigma_2 \ge \dots \ge \sigma_n \ge 0 \tag{98.2} \]
    Read the symbols
    \(\sigma_i\)
    the \(i\)-th singular value: how much of the matrix lies in the \(i\)-th piece
    \(\mathbf{u}_i, \mathbf{v}_i\)
    unit-length column and row directions of that piece

    If we keep only the first \(r\) pieces we get \(P_r\), a rank-\(r\) matrix. The Eckart–Young theorem says no other rank-\(r\) matrix is closer to \(P\), and it gives the error exactly:

    \[ \min_{\operatorname{rank}(\tilde P) \le r} \lVert P - \tilde P \rVert_F = \lVert P - P_r \rVert_F = \sqrt{\textstyle\sum_{i \gt r} \sigma_i^2} \tag{98.3} \]

    Here \(\lVert \cdot \rVert_F\) is the Frobenius norm, the square root of the sum of all squared entries. So the question “is \(P\) low rank?” becomes: do the singular values fall fast? If they do, a small \(r\) leaves a small error.

    Why it can be low rank, and why not always

    The score matrix \(QK^\top\) has rank at most \(d\) (for example 64), because it is a product of an \(n \times d\) and a \(d \times n\) matrix. But the softmax takes the exponential of each entry, and that breaks the rank: \(P\) can have full rank \(n\). What matters is how sharp the attention is.

    • If attention is smooth (many tokens get similar weights), rows of \(P\) look alike and few directions are needed.
    • If most rows put their weight on the same few tokens (for example a first token that collects attention, often called an “attention sink”), \(P\) is close to rank 1.
    • If each token attends sharply to its own neighbours (a local or “previous token” head), \(P\) is close to a shifted identity matrix, and an identity matrix has full rank. Low-rank methods cannot copy this pattern well.

    Linformer measured real models. They took RoBERTa-base (12 layers) and RoBERTa-large (24 layers) at \(n = 512\), ran an SVD of \(P\) for every layer and head, and averaged over 10,000 sentences of Wiki103 and IMDB. The spectrum had a long tail: most of the mass sat in the first singular values. They also found that higher layers were more low rank than lower layers. [Certain] Figure 1 lets you see all three cases on a small synthetic matrix.

    AnalogyThink of a class of 500 students, each writing down how much they trust every other student. If most students trust the same few class leaders, the table is easy to summarize: “who are the leaders, and how much does each student follow them”. If every student only trusts their own desk neighbour, there is no short summary; you must write down the whole table.

    Linformer also gives a theoretical reason. Their Theorem 1 uses the Johnson–Lindenstrauss lemma (a random projection to \(k\) dimensions keeps lengths and distances almost unchanged): for any value vector \(\mathbf{w}\), a random matrix \(R \in \R^{k \times n}\) with entries from \(\mathcal{N}(0, 1/k)\) gives \(\lVert P R^\top R \mathbf{w} - P\mathbf{w} \rVert \le \varepsilon \lVert P\mathbf{w} \rVert\) with high probability when

    \[ k = \frac{5 \ln n}{\varepsilon^2 - \varepsilon^3} \tag{98.4} \]

    This grows only like \(\log n\). But the constant is large: for \(n = 512\) and \(\varepsilon = 0.5\) it gives \(k \approx 250\), and for \(\varepsilon = 0.1\) it gives \(k \approx 3{,}466\), larger than \(n\) itself. So the theorem tells us the direction (rank can be much smaller than \(n\)), and the experiments tell us the useful values (\(k = 128\) to \(256\)). [Certain]

    Linformer: project keys and values from n to k

    A low-rank \(P\) suggests computing an SVD, but an SVD of every attention matrix would cost more than it saves. Linformer’s trick is cheaper. Before attention, it multiplies the keys and the values by two learned matrices \(E, F \in \R^{k \times n}\). Each row of \(EK\) is a learned weighted sum of all \(n\) key rows, so \(EK\) is a short “summary sequence” of \(k\) keys. The same for \(FV\). Then normal attention runs between the \(n\) queries and the \(k\) summary rows:

    \[ \bar P = \softmax\!\left(\frac{Q\,(E K)^\top}{\sqrt{d}}\right) \in \R^{n \times k}, \qquad O = \bar P\,(F V) \in \R^{n \times d} \tag{98.5} \]
    Read the symbols
    \(E, F\)
    learned projection matrices of shape \(k \times n\); \(E\) mixes the keys, \(F\) mixes the values. They are trained with the rest of the model
    \(EK, FV\)
    \(k \times d\) matrices: \(k\) summary keys and \(k\) summary values
    \(\bar P\)
    an \(n \times k\) attention matrix: each token distributes its weight over \(k\) summaries instead of \(n\) tokens

    The queries are not projected, so the output still has one row per token. Linformer’s Theorem 2 says that with suitable \(E\) and \(F\), a \(k\) of order \(d \log d / \varepsilon^2\) is enough, independent of \(n\). [Certain] Note what is learned: \(E\) is a fixed matrix; it does not depend on the content of this particular sequence, only on positions.

    The cost

    Per head, we have four matrix products: \(EK\) and \(FV\) (\(2knd\) FLOPs each), \(Q(EK)^\top\) (\(2nkd\)) and \(\bar P (FV)\) (\(2nkd\)):

    \[ \text{FLOPs}_{\text{Lin}} \approx 8\, n k d, \qquad \frac{\text{FLOPs}_{\text{full}}}{\text{FLOPs}_{\text{Lin}}} = \frac{4 n^2 d}{8 n k d} = \frac{n}{2k}, \qquad \frac{\text{score memory}_{\text{full}}}{\text{score memory}_{\text{Lin}}} = \frac{n^2}{nk} = \frac{n}{k} \tag{98.6} \]

    Linear in \(n\) for a fixed \(k\). The FLOP saving only starts when \(n \gt 2k\): with \(k = 256\), Linformer does more work than full attention below 512 tokens.

    Worked example: \(n = 4096\), \(k = 256\), \(d = 64\), one head

    Full attention: \(4 \times 4096^2 \times 64 = 4.29 \times 10^9\) FLOPs, and a score matrix of \(4096^2 = 16.8\) million entries (32 MiB in FP16).

    Linformer: \(8 \times 4096 \times 256 \times 64 = 5.37 \times 10^8\) FLOPs, which is \(n/(2k) = 8\) times less, and a score matrix of \(4096 \times 256 = 1.05\) million entries (2 MiB), which is \(n/k = 16\) times less.

    New parameters: \(E\) and \(F\) have \(256 \times 4096 = 1{,}048{,}576\) entries each. In a 12-layer, 12-head model without sharing that would be 288 such matrices. Linformer tried three kinds of sharing: headwise (one \(E\) and one \(F\) per layer: 24 matrices), key-value (\(E = F\) per layer: 12) and layerwise (one matrix for the whole model: 1). Even layerwise sharing gave almost the same validation perplexity. [Certain]

    What the experiments showed

    Linformer pretrained masked language models (the RoBERTa recipe on BookCorpus plus English Wikipedia, 250k updates on 64 V100 GPUs). With \(n = 512, k = 128\) and \(n = 1024, k = 256\), validation perplexity was “nearly on par” with the standard Transformer. When they grew \(n\) from 512 to 4096 with \(k = 256\) fixed, the final perplexity stayed about the same. [Certain] On four fine-tuning tasks (SST-2, IMDB, QNLI, QQP), the average accuracy was:

    Model (\(n = 512\))Average of 4 tasks
    RoBERTa-base (same corpus as BERT)92.25
    Linformer, \(k = 128\)91.75
    Linformer, \(k = 256\)92.08
    Linformer, \(k = 256\), one shared matrix for the whole model92.30

    All numbers are from Linformer’s Table 2. [Certain] Two cautions. These are short-sequence, bidirectional encoder tasks, where low rank is easiest. And on the Long Range Arena benchmark (Tay et al.), whose tasks have 1K to 8K tokens, Linformer’s average was 51.36 against 54.39 for the standard Transformer, as reported in the Luna paper’s Table 1. [Certain]

    Other ways to shrink n to k

    The projection does not have to be a learned matrix. Linformer mentions mean or max pooling and a strided convolution with kernel and stride \(n/k\). [Certain] Pooling has one big advantage: it has no parameters that depend on \(n\), so it works for any length. It also has a clear meaning: summary \(j\) is the average of tokens \(j \cdot n/k\) to \((j+1) \cdot n/k - 1\). Nyströmformer (Xiong et al., 2021) builds the low-rank form in another way, from a few “landmark” rows and columns of the attention matrix (the Nyström method). [Certain] Linformer also suggests a non-uniform \(k\): a smaller \(k\) in higher layers, where the spectrum falls faster.

    Algorithm 1: one Linformer attention layer (encoder, length \(n\))
    1. input: \(X \in \R^{n \times d_{\text{model}}}\); weights \(W^Q_h, W^K_h, W^V_h\) per head, \(W^O\); projections \(E, F \in \R^{k \times n_{\max}}\) (shared by heads)
    2. for each head \(h\):
    3.   \(Q, K, V \leftarrow X W^Q_h,\ X W^K_h,\ X W^V_h\) // each n × d
    4.   \(\bar K \leftarrow E_{[:, :n]}\, K\), \(\;\bar V \leftarrow F_{[:, :n]}\, V\) // k × d summaries, cost 4knd
    5.   \(\bar P \leftarrow \softmax(Q \bar K^\top / \sqrt{d})\) // n × k, never n × n
    6.   \(O_h \leftarrow \bar P\, \bar V\) // n × d
    7. return \(\operatorname{concat}_h(O_h)\, W^O\) // padding positions must be zeroed in K and V before the projection

    Set Transformer and Luna: pack, then unpack

    Linformer’s summaries are built with fixed weights \(E\). The weight of token 17 in summary 3 is the same for every input. A more flexible way is to let the summaries choose what to read, using attention itself.

    AnalogyA large meeting with \(n\) people. Instead of everyone talking to everyone (\(n^2\) conversations), \(l\) reporters walk around and each writes notes on what they find relevant (pack). Then each person reads the \(l\) notes (unpack). Linformer is a version where the reporters are told in advance which seats to listen to; in Luna, the reporters decide by themselves, based on what they hear.

    Take \(l\) learned vectors, stacked in \(P_{\text{q}} \in \R^{l \times d}\) (for example \(l = 16\)). Use them as queries that attend over the \(n\) tokens. The output is \(l\) vectors that summarize the sequence. Then let every token attend over those \(l\) summaries. Luna calls these two steps pack and unpack:

    \[ Y_P = \operatorname{Attn}(P_{\text{q}},\, X) \in \R^{l \times d}, \qquad \text{cost } O(l n d) \tag{98.7} \]
    \[ Y_X = \operatorname{Attn}(X,\, Y_P) \in \R^{n \times d}, \qquad \text{cost } O(n l d) \tag{98.8} \]
    Read the symbols
    \(\operatorname{Attn}(A, C)\)
    ordinary softmax attention with queries from \(A\) and keys and values from \(C\) (each with its own learned projections)
    \(P_{\text{q}}\)
    the \(l\) learned query vectors (Luna writes \(P\); we add “q” so it is not confused with the attention matrix)
    \(Y_P\)
    the packed context: \(l\) summary vectors, each a softmax-weighted average of token values
    \(Y_X\)
    the output, one row per token, as in full attention

    Both steps are normal attention, so both are exact softmax operations; only the route is different. Information goes from token \(j\) to token \(i\) through the \(l\) summaries. Written as one matrix, the effective token-to-token weights are \(A_{\text{unpack}} A_{\text{pack}}\), an \(n \times l\) times \(l \times n\) product, so its rank is at most \(l\). This is low-rank attention again, but now the factors depend on the content of the input.

    Set Transformer: inducing points

    The Set Transformer was built for inputs that are sets (point clouds, a bag of image features), where the order of the items must not matter. Its basic block is the multihead attention block \(\operatorname{MAB}(X, Y) = \operatorname{LayerNorm}(H + \operatorname{rFF}(H))\) with \(H = \operatorname{LayerNorm}(X + \operatorname{Multihead}(X, Y, Y))\), where rFF is a row-wise feed-forward layer. Full self-attention on a set is \(\operatorname{SAB}(X) = \operatorname{MAB}(X, X)\), which costs \(O(n^2)\). The induced set attention block uses \(m\) learned inducing points \(I \in \R^{m \times d}\):

    \[ H = \operatorname{MAB}(I, X) \in \R^{m \times d}, \qquad \operatorname{ISAB}_m(X) = \operatorname{MAB}(X, H) \in \R^{n \times d}, \qquad \text{cost } O(nm) \tag{98.9} \]

    This is exactly pack (98.7) and unpack (98.8), two years before Luna. The paper itself calls it “analogous to low-rank projection or autoencoder models”. [Certain] To get one fixed-size output for the whole set (for example for classification), the Set Transformer uses pooling by multihead attention with \(k\) learned seed vectors \(S\):

    \[ \operatorname{PMA}_k(Z) = \operatorname{MAB}\big(S,\ \operatorname{rFF}(Z)\big) \in \R^{k \times d} \tag{98.10} \]

    PMA is a pack step without an unpack. Remember it: it is the same shape of computation as the Q-Former and the Perceiver Resampler in VLMs, where a fixed number of learned queries cross-attends to a variable number of image or video features (session 178).

    Luna: carry the summary from layer to layer

    Luna adds one more idea. In the Set Transformer the inducing points are fixed parameters, the same for every input. In Luna, only the first layer starts from learned vectors (learned positional embeddings). Each layer outputs the packed context \(Y_P\) as a second output, and the next layer uses it as its \(P_{\text{q}}\). So the summary is contextual: it is refined layer by layer, like a small side memory. [Certain] Luna also shares \(W^Q\) and \(W^K\) inside each layer to save parameters, following Linformer.

    Luna points out two advantages over Linformer. First, pack attention does not depend on \(n\), so sequences of any length work; Linformer’s \(E\) has a fixed number of columns. Second, the contextual summary is more expressive. [Certain] On Long Range Arena, Luna with \(l = 16\) averaged 61.46, against 59.24 for the authors’ re-run of the standard Transformer and 51.36 for Linformer. Luna-16 trained 1.2× to 5.5× faster than the Transformer (from 1K to 4K tokens) and used 10% of its peak memory at 4K. [Certain] Note that the authors trained the Retrieval task for 20K steps instead of 5K, while the other baselines come from Tay et al.; their re-run Transformer most likely used the longer setting too (its Retrieval score is 79.14 against 57.46 in Tay et al.). [Likely]

    Algorithm 2: one Luna layer (encoder)
    1. input: tokens \(X \in \R^{n \times d}\), packed memory \(P_{\text{q}} \in \R^{l \times d}\) (learned for layer 1, the previous layer’s \(P'\) otherwise)
    2. \(Y_P \leftarrow \operatorname{Attn}(P_{\text{q}}, X)\) // pack: l queries over n tokens, O(lnd)
    3. \(Y_X \leftarrow \operatorname{Attn}(X, Y_P)\) // unpack: n queries over l summaries, O(nld)
    4. \(X_A \leftarrow \operatorname{LayerNorm}(Y_X + X)\), \(\;P' \leftarrow \operatorname{LayerNorm}(Y_P + P_{\text{q}})\)
    5. \(X' \leftarrow \operatorname{LayerNorm}(\operatorname{FFN}(X_A) + X_A)\) // FFN only on the token stream
    6. return \(X', P'\) // both go to the next layer

    A cousin: Funnel-Transformer

    The methods above keep \(n\) tokens and shorten only the keys and values. Funnel-Transformer gradually compresses the sequence of hidden states itself to a shorter one as it goes deeper, so later blocks run on fewer tokens, and a decoder can recover a representation for every token when a task needs one. [Certain] The compression is done by pooling along the sequence, and within a block the attention is still full, but over a shorter sequence. [Likely] This is the same bet (much of a long sequence is redundant), placed on the token axis instead of the key axis. The same idea appears in VLMs as visual token pooling or merging (session 206).

    The limits: causal masking and variable length

    Why causal masking breaks Linformer

    A decoder LLM must not let token \(i\) see tokens after \(i\) (session 18). In full attention this is easy: set the scores for \(j \gt i\) to \(-\infty\). In Linformer there is no score per token pair. Token \(i\) attends to the summary rows, and summary row \(j\) is

    \[ (EK)_j = \sum_{t=1}^{n} E_{jt}\, \mathbf{k}_t \tag{98.11} \]

    a mix of all keys, including those of future tokens. There is no entry to mask. If we train a decoder this way, every token can read the future through the summaries, the training loss becomes easy, and generation fails because the future does not exist yet. Figure 4 shows the leak.

    The fix is to give each position its own summary of the past only:

    \[ \bar K^{(i)} = \sum_{t=1}^{i} E_{:,t}\, \mathbf{k}_t^\top \in \R^{k \times d}, \qquad \bar K^{(i)} = \bar K^{(i-1)} + E_{:,i}\, \mathbf{k}_i^\top \tag{98.12} \]

    This is correct, and the right-hand form even looks attractive for decoding: the state has a fixed size \(k \times d\), updated once per new token, like a KV cache that never grows. But it has three costs. (1) Training needs a different \(\bar K^{(i)}\) for every \(i\): either \(n\) states of size \(k \times d\) in memory, or a sequential scan, which loses the parallelism of transformers. For \(n = 4096\), \(k = 256\), \(d = 64\) those states hold 67.1 million numbers per head, four times the 16.8 million entries of the full score matrix we wanted to avoid. (2) For small \(i\) the summary holds only a few tokens, while the projection was designed for \(n\). (3) The softmax runs over \(k\) mixed summaries, so a decoder cannot reliably pick out one exact earlier token, which is what copying and “needle in a haystack” retrieval need. [Likely] Pooled summaries have a simpler causal version: a query can use only the summaries of blocks that have fully ended, plus exact attention inside its own block.

    Luna faces the same problem. It states that causal attention is “not straight-forward” in Luna, because the packed sequence mixes all positions. Its causal version replaces the softmax in the pack step with \(\operatorname{elu}(\cdot) + 1\) or softplus (a softmax would normalize over future positions), uses cumulative sums over the prefix, and needs sequential computation for each time step, like the linear attention of the next session. [Certain]

    Why variable lengths are awkward

    \(E\) has a fixed number of columns \(n_{\max}\). A shorter input must be padded and the padding keys and values must be set to zero before the projection, or the summaries absorb padding. In practice one uses only the first \(n\) columns, \(E_{[:, :n]}\). Then the summary for a 100-token input is built from weights that were trained to cover 4,096 positions, and its scale changes with \(n\). A longer input than \(n_{\max}\) cannot be processed at all without new weights. [Likely] Pooling (window \(n/k\)) or pack attention (Luna, Set Transformer) avoids this, which is one reason the pack idea survived and the fixed \(E\) did not.

    And the KV cache?

    For inference, the main pain of decoder LLMs at long context is the KV cache read in every decode step (session 80). Full attention keeps all \(n\) keys and values so that any one of them can be retrieved exactly later. A low-rank method keeps a fixed \(k\)-row summary and accepts that some details are lost. That is a real trade: you gain a constant-size state, and you lose exact recall. Today’s LLMs mostly prefer to shrink the cache in other ways (GQA and MLA in session 97, sparse and windowed attention in session 116) and keep exact softmax attention, computed with FlashAttention. [Likely] Low-rank and pack-style attention stay popular where the input is long but the output is short and bidirectional: encoders, perception and vision-language connectors.

    Runnable code

    A multi-head Linformer layer, a pack/unpack layer, and two checks: with \(k = n\) and \(E = F = I\) Linformer must equal full attention exactly, and pack/unpack must accept any length. The last block measures the best rank-\(r\) error (98.3) of a random softmax matrix.

    import math, torch, torch.nn as nn, torch.nn.functional as F
torch.manual_seed(0)

class LinformerSelfAttention(nn.Module):
    """Multi-head Linformer attention, formula (98.5). One E and one F per layer (headwise sharing)."""
    def __init__(self, d_model, n_heads, max_len, k):
        super().__init__()
        self.h, self.dh = n_heads, d_model // n_heads
        self.qkv = nn.Linear(d_model, 3 * d_model)
        self.out = nn.Linear(d_model, d_model)
        self.E = nn.Parameter(torch.randn(k, max_len) / math.sqrt(k))   # projects keys:   n to k
        self.F = nn.Parameter(torch.randn(k, max_len) / math.sqrt(k))   # projects values: n to k
    def forward(self, x):                          # x: (B, n, d_model), n at most max_len
        B, n, _ = x.shape
        q, k, v = self.qkv(x).view(B, n, 3, self.h, self.dh).permute(2, 0, 3, 1, 4)  # each (B, h, n, dh)
        k = torch.einsum("jn,bhnd->bhjd", self.E[:, :n], k)              # (B, h, k, dh)
        v = torch.einsum("jn,bhnd->bhjd", self.F[:, :n], v)              # (B, h, k, dh)
        o = F.scaled_dot_product_attention(q, k, v)                      # scores are (n x k), not (n x n)
        return self.out(o.transpose(1, 2).reshape(B, n, -1))

def attn(q, k, v):                                  # plain softmax attention, formula (98.1)
    return torch.softmax(q @ k.transpose(-1, -2) / math.sqrt(q.shape[-1]), -1) @ v

class PackUnpack(nn.Module):
    """Luna / Set Transformer (ISAB) idea, formulas (98.7)-(98.9), single head, no FFN."""
    def __init__(self, d, l):
        super().__init__()
        self.P = nn.Parameter(torch.randn(l, d))   # l learned queries (inducing points)
        self.q1, self.k1, self.v1 = nn.Linear(d, d), nn.Linear(d, d), nn.Linear(d, d)
        self.q2, self.k2, self.v2 = nn.Linear(d, d), nn.Linear(d, d), nn.Linear(d, d)
    def forward(self, x):                           # x: (B, n, d), any n
        P = self.P.expand(x.shape[0], -1, -1)
        Yp = attn(self.q1(P), self.k1(x), self.v1(x))      # pack:   (B, l, d), cost O(l n d)
        Yx = attn(self.q2(x), self.k2(Yp), self.v2(Yp))    # unpack: (B, n, d), cost O(n l d)
        return Yx, Yp

# 1) sanity check: with k = n and E = F = identity, Linformer is exactly full attention
n, d = 16, 32
m = LinformerSelfAttention(d, n_heads=4, max_len=n, k=n)
with torch.no_grad():
    m.E.copy_(torch.eye(n)); m.F.copy_(torch.eye(n))
x = torch.randn(2, n, d)
q, k, v = m.qkv(x).view(2, n, 3, 4, 8).permute(2, 0, 3, 1, 4)
full = m.out(attn(q, k, v).transpose(1, 2).reshape(2, n, d))
print("k = n, E = I, max diff:", (m(x) - full).abs().max().item() < 1e-5)     # True

# 2) shapes and the size of the score matrix
m = LinformerSelfAttention(d_model=512, n_heads=8, max_len=4096, k=256)
x = torch.randn(1, 4096, 512)
print(m(x).shape, "scores per head:", 4096 * 256, "instead of", 4096 * 4096)

# 3) pack/unpack works for any length, because no weight depends on n
pu = PackUnpack(d=64, l=16)
for n in (100, 1000):
    Yx, Yp = pu(torch.randn(1, n, 64))
    print(n, tuple(Yx.shape), tuple(Yp.shape))     # (1, n, 64) (1, 16, 64)

# 4) best rank-r error of a random softmax matrix (Eckart-Young, formula 98.3)
Q, K = torch.randn(512, 64), torch.randn(512, 64)
P = torch.softmax(Q @ K.T / 8, -1)
s = torch.linalg.svdvals(P)
for r in (16, 64, 128):
    err = (s[r:] ** 2).sum().sqrt() / (s ** 2).sum().sqrt()
    print(f"rank {r}: relative error {err:.3f}")    # about 0.670, 0.425, 0.291

    Look at the last result. Attention between random 64-dimensional queries and keys is not very low rank: even rank 128 of 512 leaves an error of about 0.29. The low-rank property Linformer reports belongs to trained models, whose attention has structure. Always measure it on your own model before you rely on it.

    Common mistakes

    • Using Linformer in a decoder without a causal fix. The summaries (98.11) mix future tokens. Training loss looks great; generation is broken.
    • Forgetting to zero padding before the projection. Masking padding in the scores is not enough, because there are no per-token scores: padded keys and values are already mixed into \(EK\) and \(FV\).
    • Expecting fewer FLOPs at short length. The FLOPs only drop when \(n \gt 2k\) (98.6). At \(n = 512\), \(k = 256\) the attention math is the same as full attention. (Linformer still measured 1.3× there, probably because the smaller score matrix lets a larger batch fit. [Likely])
    • Comparing attention FLOPs and calling it model speed. The FFN and projections are unchanged; Linformer’s measured 20× at 64K tokens is far below the 256× drop in attention FLOPs.
    • Assuming low rank without measuring. Local, copying and induction heads are close to full rank (Figure 1, “Local”). Check the spectrum of your own model, per layer.
    • Thinking FlashAttention and Linformer solve the same problem. FlashAttention gives the exact result with less memory traffic but the same \(n^2\) FLOPs; Linformer changes the result to reduce FLOPs.
    • Feeding a longer sequence than \(n_{\max}\). \(E\) has no columns for it. Use pooling or pack attention if lengths vary a lot.

    Interview questions

    How does Linformer reach linear complexity in sequence length?basic
    It multiplies the keys and values by learned \(k \times n\) matrices \(E\) and \(F\), giving \(k\) summary keys and values. The attention matrix is then \(n \times k\) instead of \(n \times n\). With \(k\) fixed, time and memory are \(O(nk)\), linear in \(n\). Per head the FLOPs are about \(8nkd\) against \(4n^2d\), a ratio of \(n/(2k)\).
    Is the attention matrix low rank? Give an argument for and against.core
    For: Linformer’s SVD of RoBERTa attention at \(n = 512\) shows a long-tail spectrum, more skewed in higher layers; heads that attend to a few common tokens (sinks, separators) are close to rank 1. Against: the softmax can make \(P\) full rank even though \(QK^\top\) has rank at most \(d\), and sharp local or copying heads are close to a shifted identity, which has full rank. So it depends on the head and layer; you must measure it.
    Why can’t you drop Linformer into a GPT-style decoder?core
    Each summary row \((EK)_j = \sum_t E_{jt}\mathbf{k}_t\) mixes all positions, including future ones, and there is no per-pair score to mask. A causal version needs a separate prefix summary for every position (98.12), which costs \(n\) states in training or a sequential scan, and its quality for early positions is poor. Also \(E\) is tied to a maximum length, and a fixed-size summary cannot do exact recall of one earlier token.
    Linformer vs Luna: what does Luna change?core
    Linformer summarizes with fixed, position-based weights \(E\). Luna summarizes with attention: \(l\) query vectors attend over the sequence (pack), so the weights depend on content and nothing depends on \(n\). Luna also passes the packed context to the next layer, so the summary becomes contextual. Results: variable lengths work, and Long Range Arena accuracy is much higher (61.46 for Luna-16 vs 51.36 for Linformer in Luna’s Table 1).
    What is an ISAB in the Set Transformer, and what is its cost?basic
    ISAB uses \(m\) learned inducing points \(I\): \(H = \operatorname{MAB}(I, X)\) packs the \(n\) set elements into \(m\) vectors, then \(\operatorname{MAB}(X, H)\) lets every element read them. The cost is \(O(nm)\) instead of \(O(n^2)\), and it stays permutation equivariant, because attention does not depend on the order of the keys.
    What do Q-Former, the Perceiver Resampler and PMA have in common?core
    All three use a fixed set of learned query vectors that cross-attend to a variable number of input features and output a fixed number of vectors (PMA with \(k\) seeds; 32 queries in BLIP-2; 64 visual tokens in Flamingo). That gives the LLM a constant visual budget, whatever the image resolution or the number of video frames. It is the pack half of pack/unpack.
    Linformer’s theorem gives \(k = 5\ln n/(\varepsilon^2 - \varepsilon^3)\). Is that a useful number in practice?advanced
    Not directly. For \(n = 512\) and \(\varepsilon = 0.1\) it gives about 3,466, larger than \(n\). It is a worst-case random-projection bound (Johnson–Lindenstrauss). It shows that the needed \(k\) grows only like \(\log n\) (and Theorem 2 gives a bound independent of \(n\)), but the useful values (\(k = 128\) to \(256\)) come from experiments with learned projections.
    You measure Linformer at 64K tokens: attention FLOPs are 256× lower, but the model is only 20× faster. Why?advanced
    Amdahl’s law: the QKV and output projections and the FFN scale linearly in \(n\) and do not change, so once attention is cheap they dominate. There is also overhead from the extra projection products and from kernels that are less tuned than plain attention. The memory saving (60× in Linformer’s Table 3) is larger because it sets the maximum batch size, and the \(n^2\) score memory was the main limit.
    How would you choose \(k\) per layer?advanced
    Measure the spectrum of \(P\) per layer and head on real data (as in Figure 1) and pick the \(k\) that keeps, for example, 90 to 99% of the singular-value mass. Linformer found higher layers more skewed, so a smaller \(k\) can go there (non-uniform projected dimension). Then validate on the downstream metric, since spectrum mass is only a proxy.
    FlashAttention or Linformer for a 16K-token encoder?core
    FlashAttention first: it is exact, needs no retraining, and removes the \(n^2\) memory, which is usually the first limit. If the \(4n^2d\) FLOPs are still too slow, a low-rank or pack method cuts them, but it changes the model (it must be trained or fine-tuned with it) and can hurt tasks that need precise token-to-token links. The choice is exact-but-quadratic vs approximate-but-linear.
    Why does mean pooling of K and V have an easier causal version than a learned \(E\)?advanced
    A pooled summary covers a known block of positions. A query at position \(i\) can safely use summaries of blocks that ended before \(i\), plus exact attention to the tokens in its own unfinished block. A learned \(E\) spreads every summary over all positions, so no summary is safe except with a per-position prefix sum. This block-summary pattern is close to what compressed-memory methods do. [Likely]

    Key takeaways

    • Full attention costs \(4n^2d\) FLOPs and an \(n \times n\) matrix per head (98.1). If \(P\) is close to rank \(k\), the SVD (98.2) and Eckart–Young (98.3) say a rank-\(k\) form loses little.
    • Trained attention is often low rank (long-tail spectrum, more so in higher layers), but sharp local and copying heads are not. Measure before you rely on it.
    • Linformer projects K and V from \(n\) to \(k\) with learned \(E, F\) (98.5): \(8nkd\) FLOPs, a ratio of \(n/(2k)\), and \(n/k\) less score memory (98.6). One shared matrix for the whole model works almost as well.
    • Set Transformer (ISAB, PMA) and Luna use \(l\) learned queries: pack the sequence into \(l\) summaries, then unpack (98.7 to 98.10). Nothing depends on \(n\), and Luna keeps the summary contextual across layers.
    • Limits: summaries mix future tokens (98.11), so causal decoding needs per-prefix states (98.12) and loses parallelism; fixed \(E\) ties the model to one length; a fixed summary cannot do exact recall. That is why decoder LLMs rarely use these methods, while VLM connectors use pack everywhere.
