    Transformer alternatives 1: state space models from HiPPO to S4

    A state space model keeps a small, fixed-size memory of the past and updates it once per token, like an RNN, but it can also be trained in parallel as one long convolution. This session builds the idea from the linear state equation, through HiPPO (how to choose the matrix so the memory really remembers) and S4 (how to compute it fast), to the simple diagonal models DSS, S4D and S5.

    Time: 3 to 4 hours (reading 2 hours, exercises 1 to 2 hours)Level: IntermediateBefore this: Sessions 7 (RNNs), 80 (the KV cache) and 99 (kernel-based attention); basic linear algebra and complex numbers

    What you will learn

    • The continuous linear state space model and how a step size Δ turns it into a discrete recurrence (zero-order hold and bilinear rules)
    • Why a time-invariant SSM is both a recurrence (fast decoding) and a convolution (parallel training), with a worked example
    • HiPPO: the state as the best polynomial summary of the past, and the HiPPO-LegS matrix
    • S4: why the HiPPO matrix cannot be diagonalized directly, and the normal-plus-low-rank trick
    • DSS and S4D: complex diagonal state matrices, the Vandermonde kernel and the S4D-Lin and S4D-Inv initializations
    • S5: one multi-input SSM computed with a parallel scan
    • Decode memory and training cost of SSMs compared with attention, and the main weakness that leads to Mamba

    Why this matters

    A transformer pays for its memory with a KV cache that grows with every token. A state space model (SSM) keeps a fixed-size memory instead: a small vector that it updates once per token, like an RNN. The trick that made SSMs work is that the same model can also be trained in parallel, as one long convolution, like a CNN.

    In the last three sessions we made attention cheaper: fewer KV heads (session 97), low-rank keys (session 98), and kernel features that turn attention into an RNN with a \(d \times d\) state (session 99). This session leaves attention behind. We build a sequence layer from a different idea: a linear differential equation that compresses the whole past into a few numbers. The efficient-inference survey puts these models in its group of “transformer alternates” and says that an “SSM exhibits linear computational and memory complexity with respect to the input sequence length”. [Certain, survey Section 5.1.3]

    The story has four steps, and each step fixed one problem of the previous one:

    • The linear SSM: one equation with two faces, a recurrence and a convolution.
    • HiPPO (2020): how to choose the matrix \(A\) so the state really remembers the past. It compresses history into the coefficients of a polynomial fit.
    • S4 (2021): how to compute the long convolution kernel fast and stably, using a “normal plus low-rank” form of the HiPPO matrix.
    • DSS, S4D, S5 (2022): it turns out a diagonal complex matrix with the right start values is enough. The code shrinks to a few lines.

    S4 was the first model to solve the Path-X task of the Long Range Arena (sequences of 16,384 steps) with 88% accuracy, where all earlier models stayed at the 50% of random guessing. [Certain, S4 paper] It is also the direct parent of Mamba (session 101), which adds input-dependent parameters on top of everything in this session.

    Interview tipTypical questions: “What are the two views of an SSM, and when do you use each?”, “What problem does HiPPO solve?”, “Why is S4’s matrix not simply diagonalized?”, “How big is the decode state of an SSM compared to a KV cache?”. All are answered with numbers below.

    The linear state space model

    Start in continuous time. A signal \(u(t)\) (one number per moment) goes in. The model keeps a state \(x(t) \in \R^N\), a vector of \(N\) numbers that summarizes the past. The state changes according to a linear differential equation, and the output \(y(t)\) is read from the state:

    \[ x'(t) = A\,x(t) + B\,u(t), \qquad y(t) = C\,x(t) + D\,u(t) \tag{100.1} \]
    Read the symbols
    \(x(t) \in \R^N\)
    the state: the model’s memory of the input so far; \(N\) is the state size (often 16 to 256)
    \(x'(t)\)
    how fast the state changes at time \(t\)
    \(A \in \R^{N \times N}\)
    the state matrix: how the memory evolves and fades on its own
    \(B \in \R^{N \times 1}\)
    how the input is written into the state
    \(C \in \R^{1 \times N}\)
    how the output is read from the state
    \(D\)
    a skip connection from input to output (a single number); often left out of the math because it is trivial

    This is the classic model of control theory and signal processing (a Kalman filter uses the same form). Two things are important. First, it is linear: no tanh, no gates. Second, \(A, B, C\) do not depend on the input or on time. Such a system is called linear time-invariant (LTI). Everything good in this session (the convolution view) comes from LTI, and the main weakness (no content-based selection) comes from it too.

    AnalogyA bathtub with several taps and drains. The input \(u\) is water poured in. The state \(x\) is the water level in \(N\) connected tanks. \(A\) says how water flows between tanks and drains away. \(C\) is where you put the measuring stick. The level now depends on everything poured in before, but old water has partly drained out.

    In a deep network, one SSM maps one channel to one channel. A layer with model width \(H\) runs \(H\) independent SSMs, one per channel, and then mixes the channels with a normal linear layer (and a nonlinearity). We come back to this in the S4 and S5 sections.

    From continuous to discrete time

    Tokens arrive at steps \(k = 0, 1, 2, \dots\), not as a continuous signal. We assume the tokens are samples \(u_k = u(k\Delta)\) of a hidden continuous signal, with a step size \(\Delta \gt 0\). Then we turn (100.1) into a rule from one step to the next. If the input is held constant during each step (a zero-order hold, ZOH), the exact solution of the differential equation over one step gives

    \[ \bar{A} = e^{\Delta A}, \qquad \bar{B} = (\Delta A)^{-1}\left(e^{\Delta A} - I\right) \Delta B \tag{100.2} \]

    S4 used the bilinear (trapezoid) rule instead, which avoids the matrix exponential:

    \[ \bar{A} = \left(I - \tfrac{\Delta}{2} A\right)^{-1}\left(I + \tfrac{\Delta}{2} A\right), \qquad \bar{B} = \left(I - \tfrac{\Delta}{2} A\right)^{-1} \Delta B \tag{100.3} \]

    Both give the same discrete model, a linear recurrence:

    \[ x_k = \bar{A}\, x_{k-1} + \bar{B}\, u_k, \qquad y_k = C\, x_k, \qquad x_{-1} = 0 \tag{100.4} \]
    Read the symbols
    \(\Delta\)
    the step size: how much continuous time one token covers. Small \(\Delta\): the state changes little per token and remembers for many tokens. Large \(\Delta\): it reacts fast and forgets fast. In S4 and S4D, \(\Delta\) is learned, one per channel
    \(\bar{A}, \bar{B}\)
    the discrete versions of \(A, B\); they depend on \(\Delta\)
    \(e^{\Delta A}\)
    the matrix exponential; for a diagonal \(A\) it is just \(e^{\Delta a_n}\) on the diagonal

    The step size behaves like a gate in an RNN: it decides how much new input enters and how much old state stays. The HiPPO paper makes this link to RNN gates explicit. [Certain, HiPPO paper Section 2.5] Note also that \(\Delta\) is the only place where “time resolution” enters. If you sample the same audio at twice the rate, you can halve \(\Delta\) and keep \(A, B, C\).

    Two views of one model

    Now the key insight. Unroll the recurrence (100.4) from \(x_{-1} = 0\):

    \[ x_0 = \bar{B} u_0, \quad x_1 = \bar{A}\bar{B} u_0 + \bar{B} u_1, \quad \dots, \quad y_k = \sum_{j=0}^{k} C \bar{A}^{j} \bar{B}\, u_{k-j} \tag{100.5} \]

    The output at step \(k\) is a weighted sum of all past inputs, and the weight of an input \(j\) steps ago is the number \(C\bar{A}^j\bar{B}\). These weights do not depend on \(k\) or on the input. So they form a fixed convolution kernel:

    \[ \bar{K} = \left( C\bar{B},\ C\bar{A}\bar{B},\ C\bar{A}^2\bar{B},\ \dots,\ C\bar{A}^{L-1}\bar{B} \right) \in \R^{L}, \qquad y = \bar{K} * u \tag{100.6} \]
    Read the symbols
    \(\bar{K}\)
    the SSM convolution kernel; one number per lag \(0, 1, \dots, L-1\)
    \(L\)
    the sequence length
    \(*\)
    causal convolution: \(y_k = \sum_{j \le k} \bar{K}_j\, u_{k-j}\)

    So one SSM has two ways to compute the same output:

    Recurrent view (100.4)Convolutional view (100.6)
    Workone state update per tokenbuild \(\bar{K}\) once, then one long convolution (FFT)
    Parallel over time?no, step \(k\) needs step \(k-1\)yes, all outputs at once
    Memory during decodethe state: \(N\) numbers per channel, for any lengthneeds all past inputs
    Used forgeneration, one token at a timetraining and prefill, all tokens known

    This is what RNNs never had. An LSTM can only be computed step by step, so its training does not use the GPU well (session 7). An LTI SSM trains like a CNN and decodes like an RNN. Figure 1 lets you check, step by step, that the two views give the same numbers.

    Worked example: a one-number SSM, both ways

    Take \(a = -1\), \(b = c = 1\), \(\Delta = 0.5\). ZOH (100.2) gives \(\bar A = e^{-0.5} = 0.6065\) and \(\bar B = (e^{-0.5} - 1)/(-1) = 0.3935\). (The bilinear rule (100.3) gives \(\bar A = 0.75/1.25 = 0.6\) and \(\bar B = 0.5/1.25 = 0.4\): close, not equal.)

    Kernel (100.6): \(\bar K = (0.3935,\ 0.2387,\ 0.1447,\ 0.0878,\ \dots)\); each entry is 0.6065 times the one before.

    Input \(u = (1, 2, 0, -1)\). Recurrence: \(x_0 = 0.3935\); \(x_1 = 0.6065 \cdot 0.3935 + 0.3935 \cdot 2 = 1.0256\); \(x_2 = 0.6221\); \(x_3 = 0.6065 \cdot 0.6221 - 0.3935 = -0.0162\).

    Convolution for the last step: \(y_3 = \bar K_0 u_3 + \bar K_1 u_2 + \bar K_2 u_1 + \bar K_3 u_0 = -0.3935 + 0 + 0.2895 + 0.0878 = -0.0162\). Same number, computed without any state.

    The same loop with a matrix state

    Figure 1 had a state of one number. With \(N \gt 1\) the state is a vector, \(\bar A\) is a matrix, and every step is a matrix times a vector. The smallest interesting case is \(N = 2\) with

    \[ A = \begin{pmatrix} -\alpha & -\omega \\ \omega & -\alpha \end{pmatrix}, \qquad \bar A = e^{\Delta A} = e^{-\alpha\Delta} \begin{pmatrix} \cos \omega\Delta & -\sin \omega\Delta \\ \sin \omega\Delta & \cos \omega\Delta \end{pmatrix} \tag{100.7} \]
    Read the symbols
    \(\alpha \gt 0\)
    the decay rate: each step shrinks the state by the factor \(e^{-\alpha\Delta}\)
    \(\omega\)
    the frequency: each step turns the state by the angle \(\omega\Delta\) (in radians)
    eigenvalues
    \(A\) has eigenvalues \(-\alpha \pm i\omega\), so this real 2 × 2 block is one complex mode written with real numbers. We meet these complex modes again in S4D (100.13)

    So the ZOH step is simple to picture: shrink and rotate the state, then add \(\bar B u_k\). The state moves on a spiral, and the kernel \(C\bar A^j \bar B\) oscillates while it decays. Figure 2 runs the whole program on the input of Figure 1, with \(B = (1, 0)^\top\) and \(C = (1, 0.5)\). First it discretizes, then it builds the kernel (the convolution view), then it runs the recurrence (the recurrent view) and checks every output against the kernel.

    With \(N\) state dimensions the kernel entries are \(C\bar{A}^j\bar{B}\) with a full matrix power. Two problems remain, and they shaped the next five years of research. First, which \(A\)? A random \(A\) gives a state that forgets fast or explodes; the model then performs badly. Second, how to compute \(\bar K\) fast: \(L\) matrix powers of an \(N \times N\) matrix cost \(O(N^2 L)\) or more. HiPPO answers the first question, S4 and its diagonal successors the second.

    HiPPO: compress the past into polynomial coefficients

    HiPPO (“high-order polynomial projection operators”) asks a clear question: if you may keep only \(N\) numbers about the past of a signal, which \(N\) numbers should they be, and how do you update them when a new sample arrives? [Certain, HiPPO paper]

    The answer: fit the history \(f(s)\), \(s \le t\), with a polynomial of degree \(N - 1\), and keep its \(N\) coefficients. As a basis use orthogonal polynomials, for example Legendre polynomials \(P_n\). “Best fit” needs a measure \(\mu^{(t)}\) that says how much each past moment counts:

    \[ c(t) = \argmin_{c \in \R^N} \int_{-\infty}^{t} \Big( f(s) - \sum_{n=0}^{N-1} c_n\, g_n^{(t)}(s) \Big)^2 \, d\mu^{(t)}(s) \tag{100.8} \]
    Read the symbols
    \(c(t) \in \R^N\)
    the memory at time \(t\): coefficients of the best polynomial fit of the past
    \(g_n^{(t)}\)
    the \(n\)-th basis polynomial, stretched to the window the measure covers
    \(\mu^{(t)}\)
    the measure: which part of the past matters. LegT: a sliding window of fixed length. LegS (“scaled Legendre”): uniform weight on the whole past \([0, t]\)

    The HiPPO paper shows that for these measures the optimal coefficients obey a linear ODE, of exactly the SSM form (100.1). For LegS it is [Certain, HiPPO Theorem 2]:

    \[ c'(t) = -\frac{1}{t} A\, c(t) + \frac{1}{t} B\, f(t) \tag{100.9} \]
    \[ A_{nk} = \begin{cases} \sqrt{2n+1}\,\sqrt{2k+1} & n \gt k \\ n + 1 & n = k \\ 0 & n \lt k \end{cases}, \qquad B_n = \sqrt{2n+1} \tag{100.10} \]

    So the HiPPO matrix is not learned at first; it is derived so that the state is the best polynomial summary of the past. It is lower triangular, and its eigenvalues are its diagonal entries \(1, 2, \dots, N\) (so \(-A\) is stable). For \(N = 3\):

    \[ A = \begin{pmatrix} 1 & 0 & 0 \\ 1.732 & 2 & 0 \\ 2.236 & 3.873 & 3 \end{pmatrix}, \qquad B = \begin{pmatrix} 1 \\ 1.732 \\ 2.236 \end{pmatrix} \]
    AnalogyA reporter who must summarize a meeting that is still going on, using only a fixed number of sentences. Each minute, the reporter rewrites the summary using only the old summary and what was just said. HiPPO gives the exact rewriting rule that keeps the summary the best possible fit of the whole meeting so far.

    The \(1/t\) factor makes LegS “scale” with time: the fit always covers the whole past, whatever its length, and the update has no window-size hyperparameter. When S4 uses this matrix inside an SSM it drops the \(1/t\) and uses a fixed, learned \(\Delta\). The basis then becomes Legendre polynomials in \(e^{-t}\), times \(e^{-t}\): an exponentially fading view of the past. [Certain, S4D paper Theorem 6] In practice, this choice of \(A\) matters a lot: the S4 paper reports that switching a simple SSM from a random \(A\) to the HiPPO matrix raised sequential MNIST accuracy from 60% to 98%. [Certain, S4 paper Section 2.2]

    Figure 3 runs the HiPPO-LegS recurrence online on a signal, then rebuilds the whole history from only the \(N\) coefficients. It also computes the best offline fit, which sees all samples at once.

    On the default signal (400 samples), the root-mean-square error of the HiPPO rebuild is 0.842 with \(N = 4\), 0.327 with \(N = 16\) and 0.050 with \(N = 64\). The best offline fits give 0.842, 0.326 and 0.052. [Certain, computed with the same code in Python]

    S4: making the HiPPO SSM fast

    HiPPO solved “which \(A\)”. The first deep model built on it, LSSL, initialized \(A\) with HiPPO-LegS and trained in the convolutional view with an FFT. [Certain, survey Section 5.1.3] But computing the kernel \(\bar K\) needed many powers of a dense \(N \times N\) matrix, which was too slow and used too much memory. S4 (Gu, Goel and Ré) made it practical: compared with LSSL it is up to 30 times faster with 400 times less memory. [Certain, S4 paper]

    Why not just diagonalize?

    If \(A = V \Lambda V^{-1}\) with a diagonal \(\Lambda\), then \(\bar A^j = V \bar\Lambda^j V^{-1}\), and powers of a diagonal matrix are trivial. The problem: for the HiPPO-LegS matrix, \(V\) is terribly conditioned. Its entries grow like \(2^{4N/3}\) [Certain, S4 Lemma 3.2]; for \(N = 64\) that is about \(10^{25.7}\). Any computation through \(V\) loses all precision in float32.

    Normal plus low-rank

    The S4 observation: HiPPO-LegS is “almost” a nice matrix. It equals a normal matrix (one that a unitary, perfectly conditioned \(V\) diagonalizes) minus a rank-1 correction [Certain, S4 Theorem 1]:

    \[ A = V \Lambda V^{*} - P\,Q^{\top} = V\left( \Lambda - (V^{*}P)(V^{*}Q)^{*} \right) V^{*} \tag{100.11} \]
    Read the symbols
    \(V\)
    a unitary matrix (complex), so multiplying by it loses no precision
    \(\Lambda\)
    a diagonal matrix of complex eigenvalues of the normal part
    \(P, Q \in \R^{N \times r}\)
    low-rank factors; for HiPPO-LegS, \(r = 1\) and \(P = Q\) with \(P_n = \sqrt{n + 1/2}\)
    \(V^{*}\)
    the conjugate transpose of \(V\)

    In S4’s sign convention (state matrix \(-A\) with \(A\) from (100.10)), the normal part has entries \(-\sqrt{(n + \frac12)(k + \frac12)}\) below the diagonal, \(-\frac12\) on the diagonal and \(+\sqrt{(n+\frac12)(k+\frac12)}\) above it. All its eigenvalues have real part exactly \(-\frac12\). We check both facts in the code below.

    With this diagonal-plus-low-rank (DPLR) form, S4 computes the kernel in three moves. It evaluates the kernel’s generating function at the \(L\) roots of unity instead of computing matrix powers. It removes the rank-1 term with the Woodbury identity. And the diagonal part reduces to a Cauchy kernel, a well-studied computation. The result is \(\tilde O(N + L)\) operations and \(O(N + L)\) memory per channel to build \(\bar K\), then an FFT convolution in \(O(L \log L)\). [Certain, S4 paper]

    Algorithm 1: one S4-style layer in the convolutional (training) view
    1. input: sequence \(u \in \R^{H \times L}\) (\(H\) channels); per channel: \(\Lambda, P, B, C, \Delta\)
    2. for each channel \(h\) in parallel:
    3.   \(\bar K_h \leftarrow\) kernel (100.6) from the DPLR form // S4: Cauchy kernel + Woodbury; S4D: Vandermonde (100.12)
    4.   pad \(u_h\) and \(\bar K_h\) to length \(2L\) // so the FFT does a causal, not circular, convolution
    5.   \(y_h \leftarrow \text{IFFT}\big(\text{FFT}(u_h) \cdot \text{FFT}(\bar K_h)\big)[0{:}L] + D_h u_h\)
    6. \(y \leftarrow\) GELU\((y)\), then a linear layer (or GLU) that mixes the \(H\) channels // the SSMs never mix channels themselves
    7. add the residual and normalize, as in a transformer block

    A real S4 network stacks such layers like transformer blocks, with the SSM in the place of attention. On WikiText-103 language modeling the S4 paper reports a perplexity of 20.95 with 249M parameters, against 20.51 for a 247M transformer, while generating 48K tokens per second against 0.8K (60 times faster). [Certain, S4 paper Table 8] Close, but not better: this gap at language is the main topic of the next session.

    DSS and S4D: a diagonal matrix is enough

    The S4 algorithm was powerful but hard to implement. Months later, Gupta, Gu and Berant showed with DSS (diagonal state spaces) that you can simply drop the low-rank term and use a purely diagonal complex \(A\); it “matches the performance of S4 on Long Range Arena tasks”. [Certain, DSS paper] The follow-up S4D (Gu, Gupta, Goel, Ré) explained why and simplified it further. Its key findings [Certain, S4D paper]:

    • Almost every matrix is diagonalizable over the complex numbers, so a diagonal complex SSM can express almost any SSM. It must be complex: real diagonal matrices give only decaying exponentials, no oscillations.
    • The diagonal of S4’s normal part (dropping the low-rank term) gives, as \(N\) grows, the same kernel as S4. That is why DSS works.
    • Expressive power is not the issue; initialization is. Random diagonal matrices perform poorly. Good start values matter.

    With a diagonal \(A = \text{diag}(a_1, \dots, a_N)\), each state dimension is an independent one-number SSM, as in Figure 1, only complex. The kernel becomes a sum of \(N\) geometric sequences:

    \[ \bar K_\ell = \sum_{n=1}^{N} C_n \bar B_n\, \bar a_n^{\,\ell}, \qquad \bar a_n = e^{\Delta a_n}, \qquad \bar B_n = \frac{e^{\Delta a_n} - 1}{a_n} B_n \tag{100.12} \]

    This is a product with a Vandermonde matrix (the matrix of powers \(\bar a_n^\ell\)), \(O(NL)\) work and very parallel. The parameters come in complex-conjugate pairs so that the kernel is real: S4D keeps only \(N/2\) modes and takes twice the real part. The two main initializations are

    \[ \text{S4D-Lin: } a_n = -\tfrac12 + i\pi n, \qquad \text{S4D-Inv: } a_n = -\tfrac12 + i\,\frac{N}{\pi}\left( \frac{N}{2n+1} - 1 \right) \tag{100.13} \]
    Read the symbols
    \(n = 0, 1, \dots, N/2 - 1\)
    the index of a complex mode
    real part \(-\frac12\)
    every mode decays at the same rate, like the normal HiPPO part; the memory length is set by \(\Delta\)
    imaginary part
    the oscillation frequency of mode \(n\). Lin: evenly spaced, like a damped Fourier basis. Inv: an inverse law that approximates the eigenvalues of S4’s HiPPO-LegS normal part
    \(\Delta\)
    initialized log-uniform in \([0.001, 0.1]\), one per channel

    With real part \(-\frac12\), a mode has decayed to 1% after \(\ln 100 / (0.5\,\Delta) \approx 9.2/\Delta\) steps: 92 steps for \(\Delta = 0.1\), 9,210 for \(\Delta = 0.001\). So the \(\Delta\) range gives the channels memories from about a hundred to about ten thousand tokens. S4D averages 85% on Long Range Arena, close to S4. [Certain, S4D paper] Figure 4 shows the poles \(\bar a_n\) and the kernel they produce.

    Algorithm 2: recurrent decoding with a diagonal SSM (one new token)
    1. input: state \(x \in \mathbb{C}^{H \times N/2}\) from the previous token, new input \(u_t \in \R^{H}\); precomputed \(\bar a, \bar B\) (they never change during generation)
    2. \(x \leftarrow \bar a \odot x + \bar B \odot u_t\) // formula (100.4), element-wise: O(HN) work
    3. \(y_t \leftarrow 2\,\text{Re}\big(\sum_n C_n x_n\big) + D \odot u_t\) // sum over modes, per channel
    4. channel mixing, residual, next layer, exactly as in training
    5. return \(y_t\) and the new \(x\) // the state size never grows: no KV cache

    S5: one multi-input SSM and a parallel scan

    S4 and S4D use a bank of \(H\) independent single-input, single-output (SISO) SSMs, one per channel, each with its own \(N\)-dimensional state. S5 (Smith, Warrington and Linderman) uses one multi-input, multi-output (MIMO) SSM instead: the whole \(H\)-dimensional input vector goes into one shared diagonal state of size \(P\), with \(B \in \mathbb{C}^{P \times H}\) and \(C \in \mathbb{C}^{H \times P}\). [Certain, S5 paper]

    Because the state is shared and smaller, S5 does not need the convolution kernel at all. It computes the recurrence (100.4) directly with a parallel scan. A scan is a “running total” for any associative operation. For the linear recurrence, each step is a pair \((\bar a_k, b_k)\) with \(b_k = \bar B u_k\), and two steps combine as

    \[ (\bar a_i, b_i) \bullet (\bar a_j, b_j) = \left( \bar a_j \odot \bar a_i,\ \ \bar a_j \odot b_i + b_j \right) \tag{100.14} \]

    This operation is associative: \((p \bullet q) \bullet r = p \bullet (q \bullet r)\). So we can combine neighbors in a tree: pairs, then pairs of pairs, and so on. With a diagonal \(\bar A\), the scan takes \(O(P \log L)\) parallel time on \(L\) processors and \(O(PL)\) total work. [Certain, S5 paper Section 2.2] S5 initializes with the diagonalized normal part of HiPPO (it calls it HiPPO-N), uses ZOH with learned \(\Delta\) per state, and averages 87.4% on Long Range Arena with 98.5% on Path-X. [Certain, S5 paper]

    Algorithm 3: parallel scan for \(x_k = \bar a \odot x_{k-1} + b_k\) (training view of S5)
    1. input: elements \(e_k = (\bar a, b_k)\) for \(k = 0, \dots, L-1\) (with a time-varying \(\bar a_k\) it works the same)
    2. up-sweep: for levels \(s = 1, 2, 4, \dots\): combine \(e_{k-s} \bullet e_k\) for all \(k\) at that level in parallel // formula (100.14)
    3. down-sweep: push the partial results back down so every position gets \(e_0 \bullet \dots \bullet e_k\)
    4. the second component of \(e_0 \bullet \dots \bullet e_k\) is \(x_k\)
    5. \(y_k \leftarrow \text{Re}(C x_k) + D u_k\) for all \(k\) in parallel

    The scan matters for history. The convolution view needs the kernel to be the same at every step (LTI). The scan does not: it works even if \(\bar a_k\) and \(b_k\) change with the input at each step. That is exactly the door Mamba walks through (session 101). The survey notes that S5 and Mamba both use a parallel scan for training instead of a convolution. [Certain, survey Section 5.1.3]

    Figure 6 runs a scan on 8 steps. It uses the simplest parallel scan (Hillis and Steele): at level \(s = 1, 2, 4, \dots\), every position \(k \ge s\) combines with position \(k - s\). After level \(s\), position \(k\) holds the combined effect of the last \(2s\) inputs, so \(\log_2 L\) levels are enough. This version does more total work than the up-sweep and down-sweep of Algorithm 3 (\(O(L \log L)\) combines instead of \(O(L)\)), but it has the same \(\log_2 L\) depth and is easier to follow.

    What it costs: SSM vs attention

    Now the inference view, which is why this session sits in this track. Per layer and per channel:

    \[ \text{training: } O(L \log L) \ \text{(FFT) or } O(L) \ \text{(scan)}, \qquad \text{decode: } O(N) \ \text{per token, state of } N \text{ numbers} \tag{100.15} \]

    Compare attention: training costs \(O(L^2)\) per channel, and decoding token \(t\) reads a KV cache of \(2t\) numbers per channel (session 80). The survey’s summary table lists the same picture: per-token decoding cost \(O(nd)\) for a transformer but \(O(d^2)\) for recurrent models such as S4. [Certain, survey Table II]

    Worked example: decode memory for one layer at 32K context

    Take width \(d = H = 4096\) and context \(L = 32{,}768\). Full multi-head attention keeps \(2 \cdot L \cdot d = 268{,}435{,}456\) numbers per layer in its KV cache, which is 512 MiB per layer in BF16. An SSM layer with \(N = 64\) keeps \(d \cdot N = 262{,}144\) numbers (as 32 complex modes per channel), 512 KiB in BF16. The ratio is \(2L/N = 1024\). And the SSM number stays the same at 1M tokens, while the KV cache grows 32 times larger.

    (A fair comparison would use GQA, which divides the KV cache by the group factor, for example by 4 or 8 (session 97). The SSM still wins by a factor of more than 100 at this length.)

    Watch outA small fixed state is also the weakness. An LTI SSM cannot decide, based on content, what to store: the kernel \(\bar K\) is the same for every input. Tasks like “copy this string” or “what was the phone number 5,000 tokens ago?” need exact recall, which a KV cache gives for free. This is why the next generation (Mamba) made \(\Delta, B, C\) depend on the input, and why many production models mix a few attention layers with many SSM layers. [Likely]

    PyTorch: an S4D layer, both views

    The code below builds the HiPPO-LegS matrix and checks the normal-plus-low-rank fact (100.11). Then it implements an S4D-Lin layer with ZOH, computes its output with the Vandermonde kernel and an FFT (training view), and again token by token with the recurrence (decode view), and checks they agree. It runs on CPU in about a second.

    import math, torch
torch.manual_seed(0)

def hippo_legs(N):
    """HiPPO-LegS (formula 100.10), with the sign used by S4: dx/dt = A x + B u."""
    n = torch.arange(N, dtype=torch.float64)
    r = torch.sqrt(2 * n + 1)
    A = torch.tril(r[:, None] * r[None, :], diagonal=-1) + torch.diag(n + 1)
    return -A, r.clone()                      # lower triangular, eigenvalues -1, -2, ..., -N

class S4DKernel(torch.nn.Module):
    """One S4D layer for H channels, N/2 complex modes per channel, ZOH discretization."""
    def __init__(self, H, N=64, dt_min=1e-3, dt_max=1e-1):
        super().__init__()
        log_dt = torch.rand(H) * (math.log(dt_max) - math.log(dt_min)) + math.log(dt_min)
        self.log_dt = torch.nn.Parameter(log_dt)
        self.log_A_re = torch.nn.Parameter(torch.log(0.5 * torch.ones(H, N // 2)))      # Re(A) = -1/2
        self.A_im = torch.nn.Parameter(math.pi * torch.arange(N // 2).repeat(H, 1).float())  # S4D-Lin
        self.C = torch.nn.Parameter(torch.randn(H, N // 2, dtype=torch.cfloat) * 0.5 ** 0.5)
        self.D = torch.nn.Parameter(torch.randn(H))

    def discrete(self):
        dt = self.log_dt.exp()[:, None]                         # (H, 1)
        A = -self.log_A_re.exp() + 1j * self.A_im               # (H, N/2); Re(A) < 0 always
        dA = torch.exp(dt * A)                                  # formula (100.2), ZOH
        dB = (dA - 1) / A                                       # B = 1: (dt A)^-1 (e^{dt A} - 1) dt B
        return dA, dB

    def kernel(self, L):
        dA, dB = self.discrete()
        powers = dA[:, :, None] ** torch.arange(L)              # Vandermonde: (H, N/2, L)
        return 2 * torch.einsum("hn,hnl->hl", self.C * dB, powers).real   # formula (100.12)

    def forward_conv(self, u):                                  # u: (B, H, L), training view
        L = u.shape[-1]
        K = self.kernel(L)
        Kf = torch.fft.rfft(K, n=2 * L); uf = torch.fft.rfft(u, n=2 * L)
        y = torch.fft.irfft(uf * Kf, n=2 * L)[..., :L]           # causal convolution, O(L log L)
        return y + self.D[:, None] * u

    def step(self, x, u_t):                                     # decode view: one token
        dA, dB = self.discrete()
        x = dA * x + dB * u_t[..., None]                         # formula (100.4); x: (B, H, N/2)
        y = 2 * (self.C * x).sum(-1).real + self.D * u_t
        return x, y

# 1) HiPPO-LegS = normal matrix minus rank 1 (formula 100.11)
A, B = hippo_legs(8)
P = torch.sqrt(torch.arange(8, dtype=torch.float64) + 0.5)
AN = A + P[:, None] * P[None, :]
print("normal part:", torch.allclose(AN @ AN.T, AN.T @ AN),
      "Re(eig):", torch.linalg.eigvals(AN).real.round(decimals=6).unique().tolist())

# 2) the two views give the same output
layer = S4DKernel(H=4, N=16)
u = torch.randn(2, 4, 300)
with torch.no_grad():
    y_conv = layer.forward_conv(u)
    x = torch.zeros(2, 4, 8, dtype=torch.cfloat); ys = []
    for t in range(u.shape[-1]):
        x, y_t = layer.step(x, u[..., t]); ys.append(y_t)
    y_rec = torch.stack(ys, -1)
print("max |conv - recurrent|:", (y_conv - y_rec).abs().max().item())
print("decode state per channel:", x.shape[-1], "complex numbers, for any length")

    Output (PyTorch 2.8, CPU): normal part: True Re(eig): [-0.5], then max |conv - recurrent|: 1.67e-06 (float32 rounding), then decode state per channel: 8 complex numbers. Two details worth copying: \(\text{Re}(A)\) is stored as a log and negated, so it can never become positive (an unstable state), and the FFT is padded to \(2L\), so the convolution is causal.

    Common mistakes

    • Diagonalizing HiPPO-LegS directly. The eigenvector matrix has entries up to about \(2^{4N/3}\); in float32 the result is noise. Use the normal part (S4, S5) or a diagonal initialization such as S4D-Lin or S4D-Inv.
    • Circular instead of causal convolution. An FFT of length \(L\) wraps the end of the sequence onto the start, so the future leaks into the past. Pad both signals to \(2L\) and keep the first \(L\) outputs.
    • Letting \(\text{Re}(a_n)\) become positive. Then \(|\bar a_n| \gt 1\) and the state explodes over long sequences. Parameterize \(\text{Re}(a_n) = -\exp(\cdot)\) as in the code.
    • Real-valued diagonal \(A\) and expecting S4 quality. Real poles give only smooth decays. In the S4D ablations, the real initialization \(a_n = -(n+1)\) (S4D-Real) does clearly worse than S4D-Lin and S4D-Inv, even though it has the same spectrum as S4-LegS. [Certain, S4D paper Section 5.2]
    • Forgetting the conjugate pairs. If you keep \(N/2\) complex modes, the real kernel is \(2\,\text{Re}(\cdot)\), not \(\text{Re}(\cdot)\). Mixing both conventions halves or doubles the output.
    • Wrong \(\Delta\) range for the data. \(\Delta\) sets the memory length (about \(9.2/\Delta\) steps for real part \(-\frac12\)). If your sequences are 100K long and \(\Delta \ge 0.01\), no channel can remember the start. For Path-X (16,384 steps) S4 and S4D lower the range from \([0.001, 0.1]\) to \([0.0001, 0.01]\). [Certain, S4D paper Appendix]
    • Treating SSM parameters like other weights. The S4 code trains \(A\), \(B\), \(\Delta\) with a smaller learning rate and no weight decay; weight decay pulls \(\text{Re}(a)\) and \(\Delta\) toward values that change the memory length. [Likely]
    • Computing the kernel in low precision. \(\bar a^\ell\) for \(\ell\) in the thousands loses precision in BF16. Keep kernel and state math in FP32 / complex64.

    Interview questions

    What is a state space model, and what are its two computational views?basic
    A linear system \(x' = Ax + Bu\), \(y = Cx + Du\), discretized with a step \(\Delta\) into \(x_k = \bar A x_{k-1} + \bar B u_k\), \(y_k = C x_k\). Because \(A, B, C\) are fixed (linear time-invariant), unrolling gives \(y = \bar K * u\) with kernel \(\bar K_j = C\bar A^j \bar B\). The recurrent view processes one token at a time with an \(N\)-dimensional state (good for decoding); the convolutional view computes all outputs in parallel with an FFT (good for training and prefill).
    Why can an SSM be trained in parallel when an LSTM cannot?core
    The SSM recurrence is linear and its coefficients do not depend on the input, so the effect of input \(j\) on output \(k\) is a fixed number \(C\bar A^{k-j}\bar B\). That makes the whole layer a convolution, which is parallel over time. An LSTM has nonlinear, input-dependent gates, so step \(k\) needs the exact state from step \(k-1\); there is no fixed kernel. (A linear but input-dependent recurrence can still be parallelized with a scan, which is what S5 and Mamba use.)
    Derive the zero-order-hold discretization.core
    Over one step, with \(u\) held constant at \(u_k\), the solution of \(x' = Ax + Bu\) is \(x(t_k + \Delta) = e^{\Delta A} x(t_k) + \int_0^\Delta e^{sA}\,ds\, B u_k\). The integral is \(A^{-1}(e^{\Delta A} - I)\). So \(\bar A = e^{\Delta A}\) and \(\bar B = A^{-1}(e^{\Delta A} - I)B = (\Delta A)^{-1}(e^{\Delta A} - I)\Delta B\). For a scalar \(a = -1\), \(\Delta = 0.5\): \(\bar A = 0.6065\), \(\bar B = 0.3935\).
    What problem does HiPPO solve, and what is the LegS matrix?core
    It answers how to keep the best fixed-size summary of a growing history online. HiPPO projects the past onto \(N\) orthogonal polynomials under a chosen measure and shows the optimal coefficients follow a linear ODE. For LegS (uniform weight on the whole past), \(c' = -\frac1t A c + \frac1t B f\) with \(A_{nk} = \sqrt{(2n+1)(2k+1)}\) below the diagonal, \(n+1\) on it, 0 above, and \(B_n = \sqrt{2n+1}\). Using it as the SSM state matrix gives the state a principled long memory, which is why S4 initializes with it; a random \(A\) performs far worse (60% vs 98% on sequential MNIST in the S4 paper’s report).
    Why does S4 not simply diagonalize the HiPPO matrix, and what does it do instead?advanced
    The HiPPO-LegS eigenvector matrix is exponentially ill-conditioned (entries up to about \(2^{4N/3}\)), so a diagonal form computed through it is numerically useless. S4 writes the matrix as normal plus low-rank, \(A = V\Lambda V^* - PQ^\top\) with unitary \(V\) and rank 1. It conjugates by \(V\) (stable) to get diagonal plus low-rank, evaluates the kernel’s generating function at roots of unity, removes the low-rank part with the Woodbury identity, and reduces the diagonal part to a Cauchy kernel: \(\tilde O(N + L)\) operations and \(O(N + L)\) memory, then an FFT convolution.
    Why does a purely diagonal SSM (DSS, S4D) work, and why must it be complex?core
    Almost all matrices are diagonalizable over \(\mathbb{C}\), and \((A, B, C)\) is equivalent to \((V^{-1}AV, V^{-1}B, CV)\), so a complex diagonal SSM can express almost any SSM. S4D showed that the diagonal of S4’s normal part gives the same kernel as S4 when \(N \to \infty\). The real difficulty is initialization: random diagonals do badly, while S4D-Lin (\(-\frac12 + i\pi n\)) or S4D-Inv (approximating the HiPPO spectrum) work. Complex values are needed for oscillating kernels; real poles only give sums of decays. The kernel becomes a Vandermonde product, a few lines of code.
    How does S5 differ from S4?core
    S4 runs \(H\) independent single-input single-output SSMs (one per channel, \(N\) states each) and mixes channels later. S5 uses one multi-input multi-output SSM with a shared diagonal state of size \(P\) and matrices \(B \in \mathbb{C}^{P\times H}\), \(C \in \mathbb{C}^{H \times P}\). Because the state is small and diagonal, S5 computes the recurrence directly with a parallel scan (\(O(PL)\) work, \(O(P\log L)\) depth) instead of building a convolution kernel. It initializes with the diagonalized HiPPO-N matrix and reports 87.4% average on LRA.
    Compare decode-time memory of an SSM and a transformer layer at 32K context.core
    Width 4096, full MHA: KV cache \(2 \cdot 32768 \cdot 4096 \approx 268\)M numbers (512 MiB in BF16) per layer, growing linearly with context. An SSM with \(N = 64\) per channel: \(4096 \cdot 64 = 262{,}144\) numbers (512 KiB), constant. Ratio \(2L/N = 1024\). With GQA the KV cache shrinks by the group factor but still grows with \(L\). Per-token work follows the same pattern: attention reads the whole cache, the SSM does \(O(HN)\) element-wise updates.
    What is the main weakness of LTI SSMs for language, and how is it addressed?advanced
    The kernel is the same for every input, so the model cannot decide based on content what to remember or ignore, and a fixed state cannot store arbitrary earlier tokens exactly. Tasks such as copying, associative recall and in-context lookup suffer; S4 reached 20.95 perplexity on WikiText-103 vs 20.51 for a transformer of similar size. Fixes: make \(\Delta, B, C\) depend on the input (selective SSMs, Mamba), which forces a scan instead of a convolution; add shift/gating structure (H3); or mix in some attention layers (hybrids such as Jamba).
    How are SSMs related to linear attention?advanced
    Both are linear recurrences with a fixed-size state, so both decode in constant memory. Linear attention keeps a \(d \times d\) state \(S_t = S_{t-1} + \phi(k_t) v_t^\top\): writes depend on the input but there is no decay. An LTI SSM keeps an \(N\)-dimensional state per channel with a learned decay \(\bar A\), but writes do not depend on content. Adding input-dependent decay to linear attention, or input-dependent \(B, C\) to an SSM, moves both toward the same family; Mamba-2 makes this “state space duality” explicit. [Likely]
    What does the step size \(\Delta\) control, and why is it learned per channel?basic
    \(\Delta\) is how much continuous time one token covers. For a mode with real part \(-\frac12\), \(|\bar a| = e^{-\Delta/2}\), so the memory decays to 1% after about \(9.2/\Delta\) steps. Small \(\Delta\) gives long memory and slow reaction, large \(\Delta\) the opposite, much like an RNN gate. Learning it per channel (initialized log-uniform in \([0.001, 0.1]\)) gives the layer a spread of timescales, from about 92 to about 9,210 tokens.

    Key takeaways

    • A linear state space model (100.1), discretized with a step \(\Delta\) (100.2, 100.3), is a linear recurrence (100.4). Because it is time-invariant, it is also a convolution with kernel \(\bar K_j = C\bar A^j\bar B\) (100.6): train in parallel, decode with a fixed state.
    • HiPPO (100.8 to 100.10) derives \(A\) so that the state holds the best polynomial summary of the past; the online update matches an offline least-squares fit.
    • S4 makes HiPPO SSMs fast and stable: normal plus low-rank (100.11), Cauchy kernel and Woodbury, \(\tilde O(N+L)\) for the kernel, FFT for the convolution. First to solve Path-X (16,384 steps).
    • DSS and S4D show a complex diagonal \(A\) is enough if it is initialized well (100.13); the kernel is a Vandermonde product (100.12). S5 uses one MIMO diagonal SSM and a parallel scan (100.14).
    • Decode memory is \(N\) numbers per channel, independent of context: 1024 times smaller than an MHA KV cache at 32K tokens with \(N = 64\). The price: an LTI kernel cannot select content, which motivates Mamba.
