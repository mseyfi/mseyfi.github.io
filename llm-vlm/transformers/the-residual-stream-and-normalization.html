    The residual stream and normalization

    Every transformer block reads from one shared vector per token and adds a small edit back to it: the residual stream. Before each read, the vector is rescaled by a normalization layer. This session explains residual connections, LayerNorm and RMSNorm, why modern LLMs put the norm before each layer (Pre-LN) instead of after it (Post-LN), and how QK-norm stops attention logits from blowing up.

    Time: 3 to 4 hours (reading 2 hours, exercises 1 to 2 hours)Level: BeginnerBefore this: Sessions 4, 17 and 21 (backprop, attention math, the FFN)

    What you will learn

    • Why a residual connection makes deep stacks trainable: the identity path in the gradient
    • The residual stream view: layers read through a norm and linear maps, and write by adding
    • Why the stream grows with depth, and why each layer needs a normalized copy
    • LayerNorm vs RMSNorm: what each removes, why RMSNorm is cheaper, and the details that matter in real code (FP32 statistics, epsilon, gain conventions)
    • Post-LN vs Pre-LN: gradients at initialization, warmup, and newer variants (sandwich norm, DeepNorm, scaled residual init)
    • Growing attention logits and the fixes: QK-norm, soft-capping and z-loss, with real values from Qwen3 and Gemma 2

    Why this matters

    A modern LLM is a stack of 30 to 100 blocks. Each block has an attention layer and a feed-forward layer. Two small pieces of plumbing hold the stack together: the residual connection (add the layer’s output to its input) and normalization (rescale a vector before a layer reads it). Without them, a deep transformer does not train.

    These pieces look boring, but they decide three things you meet in practice. First, whether training is stable: where you put the normalization changes whether you need a long warmup and whether the loss suddenly jumps to NaN. Second, how to think about what the model does: the residual connections create one shared vector per token, the residual stream, and every layer reads from it and writes into it. Interpretability work is built on this view. Third, speed and numerics: normalization runs dozens of times per token, so a cheaper version (RMSNorm) is used by almost every new open model, and its details matter for mixed precision and quantization.

    The residual connection

    Take one layer \(F\) (attention or a feed-forward network). A plain network replaces its input: \(\mathbf{x}_{\text{new}} = F(\mathbf{x})\). A residual connection (also called a skip connection) keeps the input and adds the layer’s output to it:

    \[ \mathbf{x}_{l+1} = \mathbf{x}_l + F_l(\mathbf{x}_l) \tag{22.1} \]
    Read the symbols
    \(\mathbf{x}_l \in \R^{d}\)
    the vector of one token before sub-layer \(l\); \(d\) is the model width (4,096 in Llama 3 8B)
    \(F_l\)
    sub-layer number \(l\): an attention layer or an FFN, together with its normalization
    \(F_l(\mathbf{x}_l)\)
    the edit that this sub-layer adds; also called the residual branch

    The idea comes from ResNet in computer vision (He et al., 2015), where it made networks with more than 100 layers trainable. [Certain] The layer no longer has to learn the full new vector. It only has to learn the change. If the best thing a layer can do is nothing, it can output zeros, and the input passes through untouched. In a plain network, “do nothing” means learning an exact identity matrix, which is hard.

    Unrolling the stack

    Apply (22.1) again and again, from the embedding \(\mathbf{x}_0\) up to the last sub-layer. Every edit stays in the sum:

    \[ \mathbf{x}_L = \mathbf{x}_0 + \sum_{l=0}^{L-1} F_l(\mathbf{x}_l) \tag{22.2} \]

    The final vector is the embedding plus all edits. Nothing is ever overwritten; information is only added. (A layer can remove information by adding the negative of something, but it has to do this on purpose.)

    Why gradients flow

    Differentiate (22.1). The Jacobian (the matrix of partial derivatives) of one residual step is the identity plus the layer’s own Jacobian:

    \[ \frac{\partial \mathbf{x}_{l+1}}{\partial \mathbf{x}_l} = I + \frac{\partial F_l}{\partial \mathbf{x}_l}, \qquad \frac{\partial \mathcal{L}}{\partial \mathbf{x}_l} = \frac{\partial \mathcal{L}}{\partial \mathbf{x}_L} \prod_{k=l}^{L-1} \left( I + \frac{\partial F_k}{\partial \mathbf{x}_k} \right) \tag{22.3} \]

    Expand the product and one term is just \(\partial \mathcal{L} / \partial \mathbf{x}_L\) times \(I\): the gradient from the loss reaches every layer directly, through the chain of identities, without being multiplied by any weight matrix. In a plain deep network, the gradient is a product of \(L\) weight Jacobians. If their typical size is a bit below 1, the product shrinks to almost zero (vanishing gradients); if a bit above 1, it explodes. The identity path is a gradient highway. This is why the session 7 session’s LSTM worked better than a plain RNN, and it is the same trick here, applied across depth instead of time.

    AnalogyThink of a shared document that passes through a team. A plain network gives each person a blank page and asks them to rewrite the whole document from memory. A residual network lets each person add a few notes to the margin of the same document. The original text is never lost, and a person with nothing useful to say just passes it on.

    The residual stream

    Elhage et al. (2021) suggested a useful way to look at (22.2). [Certain] Do not think of the transformer as a pipe from layer to layer. Think of one residual stream per token: a vector of width \(d\) that runs from the embedding at the bottom to the output layer at the top. Each attention and FFN layer is a reader and writer attached to this stream:

    • Read: the layer normalizes the stream and applies linear maps (for example \(W_Q, W_K, W_V\) in attention, or \(W_1\) in the FFN). Each linear map picks out some directions of the stream.
    • Write: the layer’s output projection (\(W_O\), or \(W_2\) in the FFN) turns its result back into a \(d\)-dimensional vector, which is added to the stream.

    Attention is the only part that moves information between token positions: it reads the streams of earlier tokens and writes into the stream of the current token. The FFN works on each position alone. At the top, a final normalization and the output matrix read the stream and give the next-token logits.

    Three consequences of this view are worth remembering. (1) The stream is a shared memory with \(d\) dimensions. Many features must share it, so they are stored in many directions at once, not one per coordinate. (2) A layer far up can directly read what a layer far down wrote, because the write was added and never replaced. (3) Because the stream is linear (only sums), you can decompose the final vector into “contribution of each layer” and study each one. A popular trick, the logit lens, applies the output layer to the stream in the middle of the network to see what the model would predict at that depth. [Likely] Figure 1 walks one token through a small stack.

    Why normalize at all?

    By (22.2), the stream is a sum of many terms. Its size changes from layer to layer and from token to token. If each edit is a random vector with about unit variance per coordinate, the variances add up, and the stream grows like the square root of the number of edits:

    \[ \E\big[\lVert \mathbf{x}_L \rVert^2\big] \approx d\,(1 + L) \quad\Rightarrow\quad \lVert \mathbf{x}_L \rVert \approx \sqrt{d\,(1+L)} \tag{22.4} \]

    (This assumes the embedding and every edit have unit variance per coordinate and are roughly uncorrelated, which is close to true at initialization.) For \(d = 64\) and \(L = 48\) this gives \(\sqrt{64 \cdot 49} = 56\); the simulation in Figure 4 measures 55.7. A layer that reads the stream directly would see inputs whose size depends on its depth, and on the token. Its weights would need a different scale at every depth, and its non-linearities (softmax, GELU) would work in different regimes. A normalization layer fixes this: it rescales the vector to a standard size before the layer reads it.

    LayerNorm

    Layer normalization (Ba et al., 2016) works on one token’s vector at a time, over its \(d\) features. [Certain] It removes the mean, divides by the standard deviation, and then applies a learned per-feature scale and shift:

    \[ \mu = \frac{1}{d} \sum_{i=1}^{d} x_i, \qquad \sigma^2 = \frac{1}{d} \sum_{i=1}^{d} (x_i - \mu)^2, \qquad \text{LN}(\mathbf{x})_i = \gamma_i\, \frac{x_i - \mu}{\sqrt{\sigma^2 + \varepsilon}} + \beta_i \tag{22.5} \]
    Read the symbols
    \(\mu, \sigma^2\)
    mean and variance of the \(d\) numbers of this one vector (not of the batch)
    \(\varepsilon\)
    a small constant (often \(10^{-5}\)) so we never divide by zero
    \(\gamma, \beta \in \R^d\)
    learned gain and bias, one per feature; they start at 1 and 0

    Two properties follow. LayerNorm is shift invariant: adding the same constant to every coordinate does not change the output. It is scale invariant: multiplying the vector by any positive number does not change the output. Before \(\gamma\) and \(\beta\), the output always has mean 0 and variance 1. Its length is therefore always about \(\sqrt{d}\).

    Why not batch normalization, which CNNs use? BatchNorm averages each feature over the examples of a batch. In language models, the batch has sequences of different lengths, the statistics during generation (one token at a time) differ from training, and the model would depend on what else is in the batch. LayerNorm uses only the token itself, so training and inference behave the same.

    Worked example: LayerNorm and RMSNorm on four numbers

    Take \(\mathbf{x} = (2, 4, 6, 8)\), with \(\gamma = 1\), \(\beta = 0\) and \(\varepsilon\) ignored.

    LayerNorm: \(\mu = 5\). Deviations \((-3, -1, 1, 3)\), so \(\sigma^2 = (9 + 1 + 1 + 9)/4 = 5\) and \(\sigma = 2.236\). Output: \((-1.342, -0.447, 0.447, 1.342)\).

    RMSNorm (next section): \(\text{RMS} = \sqrt{(4 + 16 + 36 + 64)/4} = \sqrt{30} = 5.477\). Output: \((0.365, 0.730, 1.095, 1.461)\).

    Now add 10 to every entry: \((12, 14, 16, 18)\). LayerNorm gives exactly the same output as before. RMSNorm gives \((0.791, 0.923, 1.055, 1.187)\): different, because RMSNorm does not remove the mean. Multiply the original by 100 instead: both outputs stay the same. The PyTorch code later in this session prints these numbers.

    RMSNorm: drop the mean

    Zhang and Sennrich (2019) asked: which part of LayerNorm actually helps? Their answer was that the rescaling (scale invariance) matters and the re-centering (removing the mean) is not needed. [Certain] RMSNorm keeps only the division by the root mean square:

    \[ \text{RMS}(\mathbf{x}) = \sqrt{\frac{1}{d} \sum_{i=1}^{d} x_i^2 + \varepsilon}, \qquad \text{RMSNorm}(\mathbf{x})_i = \gamma_i\, \frac{x_i}{\text{RMS}(\mathbf{x})} \tag{22.6} \]
    Read the symbols
    \(\text{RMS}(\mathbf{x})\)
    root mean square: the typical size of one coordinate, without subtracting the mean
    \(\gamma \in \R^d\)
    learned gain, one per feature; there is no bias \(\beta\)

    What each one removes, in one sentence each:

    • LayerNorm removes the mean (one direction, the all-ones direction) and the overall size of the vector.
    • RMSNorm removes only the overall size. The output always has RMS 1, so length \(\sqrt{d}\), but its mean can be anything.

    Note that if the mean is already 0, the two are identical, since then \(\sigma = \text{RMS}\). Why is RMSNorm cheaper? LayerNorm needs two reductions over the vector (first the mean, then the variance of the centered values; or one fused pass that tracks both sums), a subtraction, and stores a bias. RMSNorm needs one reduction (sum of squares) and one multiply. Normalization does little arithmetic but reads and writes the whole activation, so on a GPU it is limited by memory traffic, and the saving comes from fewer passes and fewer parameters to read. The paper reports that RMSNorm “reduces the running time by 7%~64% on different models” compared with LayerNorm, with similar quality. [Certain] Nearly all recent open LLMs use RMSNorm: Llama, Mistral, Qwen, Gemma, DeepSeek. [Likely] GPT-2, BERT and most vision transformers use LayerNorm. [Certain] Figure 2 lets you see the difference.

    Small details that matter in real code

    • Compute the statistics in FP32. In BF16, the sum of 4,096 squares loses precision. The Hugging Face Llama code casts to FP32, computes the RMS, normalizes, and casts back. [Certain]
    • \(\varepsilon\) is a real hyper-parameter. Llama 3.1 8B uses \(10^{-5}\); Qwen3 8B and Gemma 2 9B use \(10^{-6}\) (from their config.json files). [Certain] Using the wrong value when you load a checkpoint changes the outputs slightly.
    • Gemma stores \(\gamma - 1\). Its RMSNorm multiplies by \((1 + w)\), with \(w\) initialized to 0. A converter that treats \(w\) as \(\gamma\) breaks the model. [Likely]
    • No weight decay on \(\gamma\) and \(\beta\). Decaying a gain toward 0 shrinks the layer’s input, as discussed in session 4.
    • Norms are tiny in parameters. Llama 3 8B has two RMSNorms per block plus a final one: \(32 \times 2 \times 4{,}096 + 4{,}096 = 266{,}240\) parameters, about 0.003% of the model.

    Where to put the norm: Post-LN vs Pre-LN

    There are two classic ways to combine a residual connection with a normalization. The original transformer (Vaswani et al., 2017) and BERT put the norm after the addition. This is Post-LN:

    \[ \text{Post-LN:}\qquad \mathbf{x}_{l+1} = \text{LN}\big(\mathbf{x}_l + F_l(\mathbf{x}_l)\big) \tag{22.7} \]

    GPT-2 moved the norm to the input of each sub-layer and added one final norm after the last block. [Certain] This is Pre-LN, and almost every LLM since then uses it:

    \[ \text{Pre-LN:}\qquad \mathbf{x}_{l+1} = \mathbf{x}_l + F_l\big(\text{LN}(\mathbf{x}_l)\big), \qquad \text{output} = \text{LN}_{\text{final}}(\mathbf{x}_L) \tag{22.8} \]

    The difference looks small, but it changes the residual stream completely. In Post-LN, there is no clean stream: every block normalizes the sum, so the identity path passes through \(L\) normalizations. In Pre-LN, the stream \(\mathbf{x}_l\) is a pure sum (22.2) that is never normalized; only copies of it are normalized before each layer reads them. The gradient highway of (22.3) is intact. Figure 3 shows the two layouts, and a third one used by some newer models.

    Why Post-LN needs warmup

    The original transformer was trained with 4,000 warmup steps, and Post-LN models are known to diverge or train badly without warmup. [Certain] Xiong et al. (2020) analyzed this at initialization. They showed that in Post-LN, the expected gradients of the parameters near the output are large, so a normal learning rate makes the top layers take huge steps at the start. Warmup hides this by starting with a tiny learning rate. In Pre-LN, the gradients are well behaved and become smaller with depth, so Pre-LN models can be trained without warmup and with less tuning. [Certain] (In practice, LLMs still use a short warmup for other reasons, such as Adam’s statistics being noisy in the first steps. [Likely])

    A second explanation (Liu et al., 2020) is the amplification effect: in Post-LN, each layer depends heavily on its residual branch, so small changes of the weights produce large changes of the output, and training becomes unstable. [Certain] Both views agree that Pre-LN is easier to train. Figure 4 is a small experiment you can run: a deep stack of random linear sub-layers, once in Post-LN and once in Pre-LN form, with the gradient of every layer measured by backpropagation.

    Variants you will see

    • Scaled residual initialization. GPT-2 scales the initial weights of the layers that write into the stream by \(1/\sqrt{N}\), where \(N\) is the number of residual layers. [Certain] Each edit then starts small, and the stream does not grow too fast with depth. Many training codes (nanoGPT, for example) do the same.
    • Sandwich norm. Gemma 2 and Gemma 3 normalize both the input and the output of each sub-layer: \(\mathbf{x} + \text{Norm}(F(\text{Norm}(\mathbf{x})))\). [Likely] The extra norm limits how much any single layer can write.
    • Norm on the output only. OLMo 2 moved the norm from the input to the output of the sub-layer, \(\mathbf{x} + \text{Norm}(F(\mathbf{x}))\), as part of its stability changes. [Likely]
    • DeepNorm. Wang et al. (2022) kept Post-LN but scaled up the identity path, \(\text{LN}(\alpha \mathbf{x} + F(\mathbf{x}))\) with \(\alpha \gt 1\), plus a smaller initialization, and trained transformers with 1,000 layers. [Certain]
    Watch outPre-LN is not free. Because the stream grows with depth while each edit has a fixed size, the deeper layers change the stream less and less in relative terms. Some work argues that the last layers of deep Pre-LN models contribute less than the first ones. [Speculation] Post-LN models, when they train well, are sometimes reported to reach slightly better quality. [Likely]

    Growing attention logits and QK-norm

    Pre-LN fixes the stream, but one more problem remains inside attention. The attention score between a query and a key is \(\mathbf{q}^\top \mathbf{k} / \sqrt{d_h}\) (session 17), with \(\mathbf{q} = W_Q \mathbf{h}\) and \(\mathbf{k} = W_K \mathbf{h}\) computed from the normalized input \(\mathbf{h}\). The norm controls \(\mathbf{h}\), but not \(W_Q\) and \(W_K\). During training these weights can grow. If both grow by a factor \(g\), the logits grow by \(g^2\):

    \[ z_j = \frac{(g\, W_Q \mathbf{h})^\top (g\, W_K \mathbf{h}_j)}{\sqrt{d_h}} = g^2\, \frac{\mathbf{q}^\top \mathbf{k}_j}{\sqrt{d_h}} \tag{22.9} \]

    A 10% growth of both matrices makes the logits 21% larger; doubling them makes the logits 4 times larger. Large logits make the softmax almost one-hot: attention puts all its weight on one key, its entropy collapses to zero, and the gradient through the softmax becomes tiny or unstable. Dehghani et al. (2023) saw this when scaling vision transformers toward 22B parameters: without a fix, training diverged, with “unstable attention values”. [Certain] Wortsman et al. (2023) reproduced “the growth of logits in attention layers” in small models trained with high learning rates. [Certain]

    The fix, QK-norm, is simple: normalize the query and the key of each head (with LayerNorm or RMSNorm over the head dimension \(d_h\)) just before the dot product:

    \[ \hat{\mathbf{q}} = \text{RMSNorm}(\mathbf{q}), \qquad \hat{\mathbf{k}}_j = \text{RMSNorm}(\mathbf{k}_j), \qquad z_j = \frac{\hat{\mathbf{q}}^\top \hat{\mathbf{k}}_j}{\sqrt{d_h}} \tag{22.10} \]

    Now the size of the logits no longer depends on the size of \(W_Q\) and \(W_K\). With gains \(\gamma = 1\), \(\lVert \hat{\mathbf{q}} \rVert = \lVert \hat{\mathbf{k}}_j \rVert = \sqrt{d_h}\), so by the Cauchy–Schwarz inequality \(|z_j| \le \sqrt{d_h}\). The model can still make attention sharp, but only by growing the small gain vectors, which is slower and more controlled. QK-norm was used in ViT-22B [Certain], and is used in Qwen3 (which also removed the QKV bias of Qwen2) [Certain], OLMo 2 [Likely] and Gemma 3 [Likely]. In Qwen3 the norm is over the head dimension, with one gain vector of size 128 shared by all heads. [Certain] Figure 5 shows the effect.

    Other fixes for runaway logits

    • Logit soft-capping (Gemma 2): squash the logits smoothly into \((-c, c)\) with
    \[ z \leftarrow c \tanh(z / c) \tag{22.11} \]
    • Gemma 2 9B uses \(c = 50\) for attention logits and \(c = 30\) for the final output logits (attn_logit_softcapping and final_logit_softcapping in its config). [Certain] A logit of 10 becomes 9.87 (almost unchanged), a logit of 100 becomes 48.2. A drawback: the tanh does not fit the fused FlashAttention kernels as easily as plain attention, which is one reason Gemma 3 switched to QK-norm. [Likely]
    • z-loss on the output logits: add a small penalty \(\alpha (\log Z)^2\), where \(Z\) is the softmax normalizer, to keep the final logits from drifting. PaLM used \(\alpha = 10^{-4}\). [Likely] Wortsman et al. show it fixes output logit divergence in their small proxies. [Likely]
    • Lower learning rate, warmup, weight decay and gradient clipping also slow down weight growth; they are covered in session 36.

    Putting it together: algorithms and code

    Here is one Pre-LN transformer block, as used (with small differences) in Llama, Qwen and Mistral, and the normalization it uses.

    Algorithm 1: RMSNorm of one token vector
    1. input: vector \(\mathbf{x} \in \R^d\) (any precision), gain \(\gamma \in \R^d\), \(\varepsilon\)
    2. \(\mathbf{x}_{32} \leftarrow\) cast \(\mathbf{x}\) to FP32 // statistics need full precision
    3. \(m \leftarrow \frac{1}{d} \sum_i x_{32,i}^2\) // one reduction; LayerNorm also needs the mean
    4. \(\mathbf{y} \leftarrow \mathbf{x}_{32} \cdot \frac{1}{\sqrt{m + \varepsilon}}\) // formula (22.6)
    5. return cast \(\mathbf{y}\) back to the input precision, times \(\gamma\)
    Algorithm 2: forward pass of a Pre-LN decoder with QK-norm
    1. input: token IDs \(t_1, \dots, t_T\)
    2. \(\mathbf{x} \leftarrow\) embedding of each token // the residual stream starts here
    3. for each block \(b = 1, \dots, N\):
    4.   \(\mathbf{h} \leftarrow \text{RMSNorm}_1(\mathbf{x})\) // read a normalized copy
    5.   \(\mathbf{q}, \mathbf{k}, \mathbf{v} \leftarrow \mathbf{h} W_Q, \mathbf{h} W_K, \mathbf{h} W_V\), split into heads
    6.   \(\mathbf{q}, \mathbf{k} \leftarrow \text{RMSNorm}_q(\mathbf{q}), \text{RMSNorm}_k(\mathbf{k})\) per head // QK-norm, formula (22.10)
    7.   \(\mathbf{x} \leftarrow \mathbf{x} + \text{Attention}(\mathbf{q}, \mathbf{k}, \mathbf{v})\, W_O\) // write: add, formula (22.1)
    8.   \(\mathbf{x} \leftarrow \mathbf{x} + \text{FFN}(\text{RMSNorm}_2(\mathbf{x}))\) // second sub-layer, same pattern
    9. \(\text{logits} \leftarrow \text{RMSNorm}_{\text{final}}(\mathbf{x})\, W_{\text{out}}\) // Pre-LN needs this final norm, formula (22.8)

    The PyTorch version. It checks our RMSNorm and LayerNorm against the built-in ones, reproduces the worked example, and runs 8 Pre-LN blocks with QK-norm to show the stream growing while the final norm brings it back to RMS 1. It runs on a CPU in about a second (tested with PyTorch 2.8).

    import math, torch
import torch.nn as nn
import torch.nn.functional as F
torch.manual_seed(0)

class RMSNorm(nn.Module):
    def __init__(self, d, eps=1e-5):
        super().__init__()
        self.eps = eps
        self.weight = nn.Parameter(torch.ones(d))   # gain only, no bias
    def forward(self, x):
        xf = x.float()                               # statistics in FP32
        rms_inv = torch.rsqrt(xf.pow(2).mean(-1, keepdim=True) + self.eps)
        return (xf * rms_inv).to(x.dtype) * self.weight

def layer_norm(x, w, b, eps=1e-5):
    mu  = x.mean(-1, keepdim=True)
    var = (x - mu).pow(2).mean(-1, keepdim=True)     # biased variance
    return (x - mu) / torch.sqrt(var + eps) * w + b

# 1) check against PyTorch
x = torch.tensor([[2., 4., 6., 8.]])
print(layer_norm(x, torch.ones(4), torch.zeros(4)))  # [-1.3416, -0.4472, 0.4472, 1.3416]
print(RMSNorm(4)(x))                                 # [0.3651, 0.7303, 1.0954, 1.4606]
print(torch.allclose(RMSNorm(4)(x), nn.RMSNorm(4, eps=1e-5)(x), atol=1e-6))                       # True
print(torch.allclose(layer_norm(x, torch.ones(4), torch.zeros(4)), nn.LayerNorm(4)(x), atol=1e-6)) # True
print(RMSNorm(4)(x + 10))                            # [0.7913, 0.9231, 1.0550, 1.1869]: a shift changes RMSNorm

# 2) a Pre-LN block with QK-norm
class Block(nn.Module):
    def __init__(self, d, n_head, qk_norm=True):
        super().__init__()
        self.h, self.dh = n_head, d // n_head
        self.norm1, self.norm2 = RMSNorm(d), RMSNorm(d)
        self.qkv = nn.Linear(d, 3 * d, bias=False)
        self.out = nn.Linear(d, d, bias=False)
        self.mlp = nn.Sequential(nn.Linear(d, 4 * d, bias=False), nn.GELU(), nn.Linear(4 * d, d, bias=False))
        self.qn = RMSNorm(self.dh) if qk_norm else nn.Identity()
        self.kn = RMSNorm(self.dh) if qk_norm else nn.Identity()
    def attn(self, x):
        B, T, D = x.shape
        q, k, v = self.qkv(x).view(B, T, 3, self.h, self.dh).unbind(2)
        q, k = self.qn(q), self.kn(k)                # normalize each head's q and k
        y = F.scaled_dot_product_attention(q.transpose(1, 2), k.transpose(1, 2), v.transpose(1, 2), is_causal=True)
        return self.out(y.transpose(1, 2).reshape(B, T, D))
    def forward(self, x):
        x = x + self.attn(self.norm1(x))             # read with a norm, write by adding
        x = x + self.mlp(self.norm2(x))
        return x

d, L = 64, 8
blocks = nn.ModuleList([Block(d, 4) for _ in range(L)])
x = torch.randn(2, 10, d)
print("start", round(x.norm(dim=-1).mean().item(), 2))  # 8.13 (about sqrt(64))
for i, blk in enumerate(blocks):
    x = blk(x)
    print(i, round(x.norm(dim=-1).mean().item(), 2))  # 8.46, 8.8, ..., 10.42: the stream grows
final_norm = RMSNorm(d)
print(final_norm(x).pow(2).mean(-1).sqrt().mean().item())  # 0.99999...: RMS 1 after the final norm

    The stream grows slowly here (8.1 to 10.4) because PyTorch’s default nn.Linear initialization makes each edit small. With the unit-variance edits of formula (22.4), it would grow much faster. Try qk_norm=False, multiply blk.qkv.weight by 4, and print the attention entropy: you will see the collapse of Figure 5.

    Common mistakes

    • Forgetting the final norm in a Pre-LN model. The stream at the top has a size that grows with depth (22.4). Feeding it straight into the output layer gives badly scaled logits.
    • Normalizing over the wrong axis. LayerNorm and RMSNorm work over the feature dimension of each token (the last axis), never over the sequence or the batch.
    • Computing the RMS in BF16 or FP16. The sum of thousands of squares loses precision or overflows in FP16. Upcast to FP32 for the statistics, as in Algorithm 1.
    • Mixing up the \(\varepsilon\) or the gain convention when you port a checkpoint (\(10^{-5}\) vs \(10^{-6}\); Gemma’s \(1 + w\)). The model still runs, so the bug is silent.
    • Thinking RMSNorm is “LayerNorm without centering, so it is worse”. In practice the quality is similar, and the next layer can absorb a common offset. It is chosen for speed and simplicity.
    • Putting dropout or a norm on the identity path (the skip connection) by accident. The skip should be a plain addition; all extra operations belong inside the residual branch.
    • Training a Post-LN model with a Pre-LN recipe. Without warmup and with a high learning rate, Post-LN often diverges early.
    • Applying weight decay to norm gains, which pushes them toward zero.

    Interview questions

    Why do transformers use residual connections?basic
    A residual connection computes \(\mathbf{x} + F(\mathbf{x})\) instead of \(F(\mathbf{x})\). The layer only learns a change, and “do nothing” is easy (output zero). For the gradient, the Jacobian of each step is \(I + \partial F / \partial \mathbf{x}\), so there is always a direct path from the loss to every layer that is not multiplied by weight matrices (22.3). This prevents vanishing and exploding gradients in deep stacks. It also creates the residual stream: a shared vector that every layer reads from and adds to.
    What is the residual stream?basic
    In a Pre-LN transformer, each token has one vector of width \(d\) that starts as the embedding and ends at the final norm. Every attention and FFN layer reads a normalized copy of it through linear maps and adds its output back. So the final vector is the embedding plus the sum of all layer outputs (22.2). Attention moves information between positions; the FFN processes each position. Interpretability tools (logit lens, probes, steering vectors) work on this stream.
    What exactly does LayerNorm compute, and what does RMSNorm drop?core
    LayerNorm takes one token’s vector, subtracts its mean over the \(d\) features, divides by the standard deviation (plus \(\varepsilon\)), then applies a learned gain and bias (22.5). RMSNorm skips the mean subtraction and the bias: it divides by the root mean square and multiplies by a gain (22.6). LayerNorm is invariant to shifts and scales of the input; RMSNorm only to scales. When the mean is zero they are equal. Example: \((2, 4, 6, 8)\) gives \((-1.342, -0.447, 0.447, 1.342)\) with LayerNorm and \((0.365, 0.730, 1.095, 1.461)\) with RMSNorm.
    Why is RMSNorm cheaper, and is it worse?core
    It needs one reduction (sum of squares) instead of a mean and a variance, no subtraction, and no bias parameter. Normalization is memory-bound, so fewer passes over the data mean less time; the RMSNorm paper reports 7% to 64% less running time depending on the model. Quality is about the same, because re-centering turned out not to be needed. That is why Llama, Qwen, Mistral and Gemma use it.
    Why not BatchNorm in a language model?core
    BatchNorm normalizes each feature using statistics over the batch. In language models, sequences have different lengths and padding, generation runs one token at a time with batch statistics different from training, and the output of one sequence would depend on the other sequences in the batch. It also needs running averages for inference. LayerNorm and RMSNorm use only the token’s own vector, so they behave the same in training and inference and need no batch statistics.
    Explain Post-LN vs Pre-LN. Which do modern LLMs use and why?core
    Post-LN: \(\text{LN}(\mathbf{x} + F(\mathbf{x}))\), the original transformer and BERT. Pre-LN: \(\mathbf{x} + F(\text{LN}(\mathbf{x}))\) with a final norm at the top, from GPT-2 on. In Pre-LN, the stream is never normalized, so the identity path from the loss to every layer is clean; gradients at initialization are well behaved, and training is stable without a long warmup. In Post-LN, the identity path passes through every norm; the top layers get large gradients at the start (Xiong et al.) and the output is very sensitive to weight changes (Liu et al.), so it needs warmup and careful tuning. Almost all LLMs use Pre-LN, now usually with RMSNorm.
    Why does a Post-LN transformer need learning-rate warmup?advanced
    Xiong et al. (2020) show that at initialization, the expected gradient of the parameters near the output of a Post-LN transformer is large and does not shrink with depth, while in Pre-LN it shrinks roughly like \(1/\sqrt{L}\). With a normal learning rate, Post-LN’s first updates are too large and training diverges or gets stuck. Warmup starts with a tiny learning rate and grows it, so the early updates stay small until the model and Adam’s statistics settle. With Pre-LN, warmup can be much shorter or removed. Liu et al. add the amplification view: Post-LN depends so strongly on each residual branch that small weight changes cause large output changes.
    Does the residual stream grow with depth? Is that a problem?advanced
    Yes, in Pre-LN. The stream is a sum of the embedding and all edits; if the edits are roughly independent with unit variance per coordinate, \(\lVert \mathbf{x}_L \rVert \approx \sqrt{d(1 + L)}\) (22.4). Each layer reads a normalized copy, so its input is fine. But the final norm divides by this growing size, so the gradient reaching each layer shrinks, and each edit changes the stream less in relative terms in deep layers. Fixes include scaled residual init (GPT-2’s \(1/\sqrt{N}\)), sandwich or output norms (Gemma, OLMo 2), and DeepNorm-like scaling. In trained models, some features of the stream become huge (“massive activations”), which matters for quantization.
    What is QK-norm and what problem does it solve?advanced
    QK-norm applies LayerNorm or RMSNorm to each head’s query and key vectors right before the dot product (22.10). Without it, if \(W_Q\) and \(W_K\) grow by \(g\), the attention logits grow by \(g^2\) (22.9); the softmax becomes one-hot, its entropy collapses and training can diverge. This was seen when scaling ViT to 22B parameters and in small models with high learning rates (Wortsman et al.). With QK-norm and gain \(\gamma = 1\), every logit is bounded by \(\sqrt{d_h}\) in absolute value. Used in ViT-22B, Qwen3, OLMo 2 and Gemma 3.
    Compare QK-norm, soft-capping and z-loss.advanced
    All three fight runaway logits. QK-norm normalizes \(\mathbf{q}\) and \(\mathbf{k}\), so attention logits are bounded by construction and depend only on directions and a small gain. Soft-capping squashes logits with \(c \tanh(z/c)\) (Gemma 2: 50 for attention, 30 for the output); it keeps small logits almost unchanged but caps large ones, and it is harder to fuse into FlashAttention. z-loss adds \(\alpha (\log Z)^2\) to the loss to keep the output softmax normalizer near 1, which stops the final logits from drifting; it does not touch attention. Modern recipes often combine QK-norm for attention with z-loss or capping for the output.
    Where would you look if a pretraining run suddenly spikes to NaN?core
    Log the max attention logit per layer, the output logit size, the gradient norm and the stream norm per layer. A growing max attention logit points to the \(g^2\) effect: add QK-norm or lower the learning rate. Growing output logits point to z-loss or capping. Check that normalization statistics are computed in FP32, that \(\varepsilon\) is right, and that norms are Pre-LN with a final norm. Then use the usual tools: lower peak learning rate, longer warmup, gradient clipping, and restarting from a checkpoint before the spike while skipping the bad batches (session 36).

    Key takeaways

    • A residual connection adds each layer’s output to its input (22.1). The stack becomes a sum of edits (22.2), and the identity path carries the gradient to every layer (22.3).
    • The residual stream is one shared vector per token. Layers read it through a norm and linear maps and write by adding. Attention moves information between tokens; the FFN works per token.
    • The stream grows with depth (22.4), so each layer reads a normalized copy. LayerNorm (22.5) removes the mean and the scale; RMSNorm (22.6) removes only the scale, is cheaper, and is used by almost all new LLMs.
    • Post-LN (22.7) normalizes the stream itself and needs warmup; Pre-LN (22.8) normalizes copies, keeps the stream clean, and needs a final norm. Modern LLMs use Pre-LN, sometimes with extra output norms.
    • Attention logits grow like \(g^2\) when \(W_Q, W_K\) grow (22.9). QK-norm (22.10) bounds them; soft-capping (22.11) and z-loss are alternatives.

    Key formulas

    \[ \mathbf{x}_{l+1} = \mathbf{x}_l + F_l(\text{Norm}(\mathbf{x}_l)), \qquad \text{RMSNorm}(\mathbf{x}) = \gamma \odot \frac{\mathbf{x}}{\sqrt{\tfrac{1}{d}\sum_i x_i^2 + \varepsilon}} \]
    \[ \text{LN}(\mathbf{x}) = \gamma \odot \frac{\mathbf{x} - \mu}{\sqrt{\sigma^2 + \varepsilon}} + \beta, \qquad z_j = \frac{\text{RMSNorm}(\mathbf{q})^\top \text{RMSNorm}(\mathbf{k}_j)}{\sqrt{d_h}} \]
