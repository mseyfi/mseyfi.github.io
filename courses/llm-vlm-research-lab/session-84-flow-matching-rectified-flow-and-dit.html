1. From noisy points to structured data

Generative diffusion and flow models start from an easy-to-sample distribution (often Gaussian noise) and learn how to transform those samples into complex data such as images or videos. In flow matching, we train a model to predict a velocity field: given an intermediate sample and its time \(t\), which direction and how far should the point move per unit time?

Analogy: directing a fleet of boats along rivers. Each boat begins at a random starting point. A learned flow field tells it which way to move as time passes, so that by the end the fleet reaches the desired destination distribution. In the simplest toy version, each boat follows a straight line from an assigned start to an assigned destination. A curved river requires a more detailed numerical route to track accurately.
Where the analogy breaks: A learned generative field defines a transformation of probability distributions, not a deterministic plan for an identified real-world boat. During training, a noise sample and a data sample may be randomly coupled; the model does not need a known one-to-one matching between individual training examples.

A Diffusion Transformer (DiT) is an architecture for predicting noise, velocity or related generative quantities using transformer blocks instead of a conventional convolutional U-Net. It is separate from the training objective: DiT can be paired with multiple generative training formulations.

2. Linear-path flow matching: derive the velocity target

Let \(z\sim p_0\) be Gaussian noise, \(x\sim p_{\mathrm{data}}\) be a training example, and \(t\sim\mathcal U[0,1]\). Consider the straight interpolation from \(z\) to \(x\):

\[x_t=(1-t)z+t x,\quad t\in[0,1].\]

Differentiate the path with respect to time:

\[\frac{dx_t}{dt}=x-z.\]

The simple conditional flow-matching regression target is therefore a velocity vector \(x-z\), with shape equal to the data representation (e.g. pixels, image latents, or video latents). We train a network \(v_\theta(x_t,t)\) to approximate the appropriate velocity field:

\[\mathcal L_{\mathrm{FM}}(\theta)=\mathbb E_{z,x,t}\left[\|v_\theta((1-t)z+tx,t)-(x-z)\|_2^2\right].\]

At inference, there is no real target example \(x\) supplied. We start with a new noise draw \(x(0)\sim p_0\), integrate the learned velocity field through time and obtain \(x(1)\), ideally distributed like the training data:

\[\frac{dx}{dt}=v_\theta(x,t),\qquad x(0)\sim p_0.\]

Important distinction: The target \(x-z\) is the derivative of each sampled conditional straight line. The velocity field learned by regression as a function of \(x_t,t\) is a conditional expectation over possible pairs, and its integral curves need not all be straight. Thus, using the target does not guarantee one-step exact generation.

3. Interactive path: change time and watch the vector move

The simplest 2D path starts at \(z=(-1,-1)\) and ends at \(x=(1,0.75)\). For teaching numerical integration we add an artificial curved offset in its y coordinate:

\[r(t)=\begin{bmatrix}-1+2t\\ -1+1.75t+0.6\sin(\pi t)\end{bmatrix},\quad r'(t)=\begin{bmatrix}2\\1.75+0.6\pi\cos(\pi t)\end{bmatrix}.\]

These equations describe an exact known toy curve. It is not a learned video diffusion model, and it is not the straight conditional flow-matching path used in the training equation above. We use it only to reveal how discretization affects integrating a velocity field.

Analogy: following a curved hiking trail. The arrow is your local walking direction at that exact position and time. A large time step may take you away from the winding trail; smaller steps can better follow the curvature, at the cost of more evaluations.

4. Why fewer denoising steps can be faster—but not always accurate

To sample from an ODE, the simplest numerical solver is forward Euler. It advances from the current point using the velocity evaluated at the current time:

\[x_{k+1}=x_k+\Delta t\,v_\theta(x_k,t_k),\qquad\Delta t=\frac{1}{N}.\]

If the true velocity varies with time or position, large steps introduce discretization error. Sophisticated numerical solvers, distilled models, consistency objectives and straighter transport paths aim to reduce the number of expensive model evaluations without sacrificing too much quality.

5. Train a tiny flow-matching velocity network in PyTorch

This runnable demonstration learns a 2D distribution, not pixels or video. It explicitly uses independent Gaussian noise and data draws rather than a paired dataset. The target is \(x_1-x_0\) and the network receives both the interpolation position and time. Then we integrate the resulting learned velocity with Euler steps.

import torch
from torch import nn

torch.manual_seed(0)
net = nn.Sequential(nn.Linear(3, 64), nn.SiLU(),
                    nn.Linear(64, 64), nn.SiLU(),
                    nn.Linear(64, 2))
opt = torch.optim.AdamW(net.parameters(), lr=2e-3)
centers = torch.tensor([[-2., 0.], [2., 0.]])

for step in range(500):
    label = torch.randint(0, 2, (256,))
    x1 = centers[label] + 0.35 * torch.randn(256, 2)  # data
    x0 = torch.randn_like(x1)                         # noise
    t = torch.rand(256, 1)
    xt = (1 - t) * x0 + t * x1
    target_velocity = x1 - x0

    predicted = net(torch.cat([xt, t], dim=-1))
    loss = (predicted - target_velocity).square().mean()
    opt.zero_grad()
    loss.backward()
    opt.step()

with torch.no_grad():
    samples = torch.randn(8, 2)
    num_steps = 32
    for i in range(num_steps):
        t = torch.full((8, 1), i / num_steps)
        velocity = net(torch.cat([samples, t], dim=-1))
        samples = samples + velocity / num_steps  # Euler update
print("Generated samples:", samples)

The training data has two clusters at approximately (-2,0) and (2,0). A sufficiently trained network should generate points distributed around these modes, but this brief demonstration provides no benchmark or guarantee of fidelity. Plot generated samples and compare against held-out real data.

Production video generation extension

A video model commonly runs in a compressed spatiotemporal latent space, potentially using a DiT that conditions on text and temporal embeddings. The data tensor could be [B,C,T,H',W'] for video latents. The velocity-prediction head must output the same latent shape, while the model must maintain temporal consistency across frames. Evaluate generation quality, motion fidelity, prompt following, temporal artifacts, GPU memory, latency and number of function evaluations (NFE) separately.

  • Baseline: train a small velocity model and sample with 32 Euler steps.
  • Keep weights and noise samples fixed; compare 1, 2, 4, 8, 16 and 32 steps.
  • Measure distribution quality and diversity instead of assuming fewer steps is universally better.
  • Compare Euler to a higher-order solver at similar NFE, then compare with a genuinely distilled model only after training it.

6. Check your understanding

In linear flow matching, what velocity target do we compute?

For \(x_t=(1-t)z+tx\), its conditional time derivative is \(x-z\). The trained model predicts a vector field conditional on its observed \(x_t,t\), averaging over possible pairs.

Why isn't a one-step sampler automatically perfect for a flow model trained on straight interpolations?

The learned marginal vector field can be curved and imperfect. Individual conditional paths can be straight without making all learned ODE trajectories straight; numerical integration and model errors remain.

How is a DiT different from flow matching?

DiT names a transformer-based architecture for denoising/generative prediction. Flow matching is a training objective and path/velocity formulation. A DiT can be trained with flow matching or other objectives.
